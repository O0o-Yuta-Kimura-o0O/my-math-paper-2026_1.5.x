# λ計算インタプリタ v8.0.1

[lambda_interpreter_v8.0.1.html](lambda_interpreter_v8.0.1.html) をブラウザで開きます。外部のスクリプト、ネット接続、インストールは不要です。原版とv8.0.0は作業フォルダに保存し、最新ファイルを配布用の `output/` に複製します。配布物に原資料の旧HTMLは含めません。

## 対象

型なし λ 計算の構文、定義展開δとβ簡約を合わせた左端最外の処理、有限証跡の再検証を扱います。自然数・真偽値・対の既存32定義に、整数と未約分分数の補助表示に関する34定義を加え、全66内蔵λ定義としました。数字 `0`–`4` はこの版ではChurch自然数の別名です。

整数は符号0/1と自然数の大きさの対であり、零の符号は正側へ正規化します。`ZAdd`・`ZSub`・`ZMul`・比較を実装し、`ZFromDiff`・`ZToDiff`で旧稿の自然数二つの差との対応を明示します。

有理数の補助表示QRepは整数二つの対で、分母は正かつ非零、未約分を許します。`QRepAdd`・`QRepSub`・`QRepMul`・比較を提供します。`QMake`・`QRepInv`・`QRepDiv`は `ResultOk` と `ResultErr` を区別して返すので、その結果を裸の分数として射影しないでください。零分母の失敗値と、有理数の零は別のデータです。

これらは指定の入力型に対するλ定義です。任意のλ項の型を自動認定するものではありません。本文の有理数Qは既約正規形であり、QRepとは区別します。λによるgcd・既約化、M・Fε・区間生成ラベルの全演算、帰納的な一般証明や収束証明の検査はHTMLに含めません。Fεや区間の別実装をβ規則の内部へ隠していません。[λ算術の定義と本文との接続](../research/lambda-arithmetic-v1.5.4.md)に仕様と手書きの対応証明があります。

内蔵の例から `ZAdd ZTwo ZMinusOne`、`QRepAdd QHalf QHalf`、`QRepInv QZero` を選べます。二つ目は約分前の4/4、三つ目は明示的な失敗値を返します。一般のChurch算術では小さい入力でも変換数が増えるため、上限内での終了と数学的な停止根拠は区別します。

構文は `x`、`λx.M`、`M N` と括弧です。`\` は `λ` の別表記です。変数名は英字または `_` から始まる英数字・`_`、または数字だけの名前です。適用は左結合、λ の本体は右端まで及びます。適用の中の λ は括弧で囲みます。`//` は行コメントです。`#`・`♭` は未実装として拒否します。

追加定義は `Name = term;`。全定義を各実行開始時にスナップショットとして固定し、定義の自由変数を使用箇所の束縛から分離します。内蔵名の上書きは可能で、上書き後の定義も証跡に記録されます。入力から参照される名前付き循環定義は、評価前の検査で拒否します。後で使われない枝にある参照もこの検査の対象です。再帰は固定点コンビネータ等の有限λ項として明示できます。未定義名は自由変数として残ります。

## 証跡

各証跡は元の入力、定義一覧、開始項、版と戦略、各段の規則・位置・前後の項、最終項、変換上限、終了状態を保持します。v8.0.1の戦略名は `leftmost-outermost-interleaved` です。δとβを合わせて左端最外の位置を選び、根にβ簡約があれば引数内の定義展開より先に処理します。使われない枝まで先行展開して項が膨らむ場合を減らします。

`expandedStart` は定義表の名前が初めて項内に残らなくなった時点の項です。その時点に未到達ならnullであり、新戦略ではそれ以前にもβ簡約が現れます。旧v8.0.0の `leftmost-outermost` 証跡は、全定義を先に展開する旧戦略で再検査します。版と戦略を取り違えた記録は拒否します。

手動停止 `stopped`、上限 `step-limit`、正規形 `normal-form`、実行エラー `error` は別の状態です。上限はδとβの合計です。QRepの `ResultErr` はλ項として正常に計算された数学上の失敗値であり、実行環境の `error` と同じものではありません。

「全履歴を JSON 保存」と「JSON を読み込み検証」で証跡を往復できます。読み込む証跡は各段の検査を通る必要があります。履歴は暗号署名ではなく、入力・定義・変換を検証する自己完結した記録です。入力や定義から一貫して作り直した別の正しい証跡を、原作者が作った証跡と識別する認証機能はありません。

内部の項は de Bruijn 添字で束縛を表します。表示時の変数名は読みやすい名前に付け直すため、入力した束縛名とは異なる場合があります。自由変数名は保持します。評価器は添字のシフトと置換で β 簡約し、再検証器は別の「束縛を直接除去する」手順で各 β 段を検査します。両者が共有する構文解析・項の構造・α 同値・位置の操作は信頼する基盤に残ります。独立した再検証は、この実装自体の形式的な正しさの証明を意味しません。

手動停止や外部エラーを記載した証跡では、有限の接頭履歴を検証します。停止操作や外部エラーが本当に起きたかは証跡だけでは証明しません。構文エラーなど開始前の失敗には変換証跡がありませんが、JSON の `failures` 欄に入力とエラーを保存します。この欄は証明証跡として認証されません。検証できる有限履歴と、任意の引数について成り立つ一般定理は区別してください。

## 検証

リポジトリのルートで、Node.js を使って次を実行します。

```sh
node verification/interpreter-tests.mjs
node verification/lambda-arithmetic-tests.mjs
```

HTML の `script#lambda-core` を DOM なしで読み込みます。公開 API は `globalThis.LambdaCore` にあり、`parse`、`print`、`alphaEqual`、`freeVariables`、`createEnvironment`、`parseDefinitions`、`splitExpressions`、`evaluate`、`verifyTrace`、`decodeNat`、`VERSION`、`SCHEMA`、`LIMITS`、`BUILTINS` を提供します。

`evaluate(source, { definitions, maxSteps, onStep, signal })` は `{ status, term, trace }` またはエラー情報を非同期で返します。`definitions` には `{name, source}` の配列を渡します。省略時は内蔵定義を使い、`[]` なら純粋な λ 項だけを評価します。`verifyTrace(trace)` は `{valid, ...}` を返します。

入力長 100,000 文字、項 50,000 ノード、深さ 512、最大 100,000 変換に制限しています。全中間項を保存するため、大きな計算はメモリを消費します。停止操作は変換の境界で処理されます。大量の記録を再検証する UI は処理中に一時的に応答しにくくなる場合があります。

実ブラウザでの画面操作は、ローカルファイルURLの表示がブラウザの安全ポリシーで拒否されたため未確認です。制約を迂回せず、計算核、UIスクリプトの構文、保存証跡、旧証跡との互換性をコードとして検査しています。最新の結果と証明の範囲は [検証資料](../verification/README.md) に記載します。
