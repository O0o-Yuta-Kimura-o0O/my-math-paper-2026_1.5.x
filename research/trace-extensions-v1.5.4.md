# 計算モデル・条件付き式変形・生成ラベルの移動 — v1.5.4

このノートは旧稿 v1.4.1 の有限計算の実例を、v1.5.x の構成に合わせて作り直したものである。自然数・整数・有理数・M多項式・Fεを作る現稿の順序を保つ。ZF、ZFC、PA、公理的な自然数対象を内部の出発点に加えない。ここで用いる帰納法は、本稿で明示した有限構文と自然数の再帰規則に関する推論である。

新しい実装は [model-extensions.mjs](../verification/model-extensions.mjs)、拒否例を含む自動検査は [model-extensions-tests.mjs](../verification/model-extensions-tests.mjs) にある。既存の自然数・有理数・Fεの小核とは独立した拡張である。

## 1. 五命令のレジスタ機械

### 1.1 有限状態と一段の規則

状態を、命令位置 `pc` と自然数の有限列 `(R0,…,Rd)` とする。命令列も有限であり、命令位置は零から数える。実行中はレジスタ数を変えない。次の五種類の命令を使う。

| 命令 | 作用 |
| --- | --- |
| `zero(r)` | `Rr` を零にし、次の命令へ進む |
| `succ(r)` | `Rr` を一つ増やし、次の命令へ進む |
| `copy(s,r)` | 変更前の `Rs` を `Rr` に複写し、次の命令へ進む |
| `jeq(r,s,k)` | `Rr=Rs` なら命令位置 `k` へ、そうでなければ次の命令へ進む |
| `halt` | 正常終了する。この命令から先の遷移は認めない |

指定したもの以外のレジスタは保持する。同じレジスタ二つを比較する `jeq(r,r,k)` は無条件の移動になる。範囲外の命令位置やレジスタ番号はエラーであり、暗黙の停止や零レジスタの追加として解釈しない。

保存形式では、レジスタの値は `"0"`, `"1"`, … という十進自然数の正準文字列とする。内部演算には BigInt を用い、Number を経由して大きな整数を丸めない。命令位置などの有限配列の添字は、別の型として範囲を検査する。これらは交換形式の記法であり、本稿の自然数と有限列へ符号化できる。十進数字を新たな数学的原始概念にはしない。

### 1.2 二つの入力を加える一つのプログラム

`R0=m`, `R1=n` を入力とし、`R2` を作業用に用いる。`R2` の初期値は任意でよい。

| 命令位置 | 命令 |
| --- | --- |
| 0 | `zero(2)` |
| 1 | `jeq(2,1,5)` |
| 2 | `succ(0)` |
| 3 | `succ(2)` |
| 4 | `jeq(2,2,1)` |
| 5 | `halt` |

**命題1.** このプログラムは任意の自然数入力 `m,n` に対して停止し、`R0=m+n` を返す。

**証明。** 命令位置1の入口で

$$
(R_0,R_1,R_2)=(m+j,n,j),\qquad 0\le j\le n
$$

が成り立つ。零化直後は `j=0` である。`j=n` なら命令5に進み、`R0=m+n` で終了する。`j<n` なら、二つの後者命令と無条件移動を経て `j+1` の入口へ戻る。従って一巡につき自然数 `n-j` が一つ減る。`n` に関する帰納法により有限回で終了し、不変条件が結論を与える。□

初期化の一手、ループ一巡の四手を `n` 回、最終分岐の一手で、遷移数は `4n+2` である。ここでは `halt` を保持した終状態までの遷移を数え、`halt` 自体は状態を移す一手に数えない。これは**任意入力についての手書きの停止・正しさ証明**である。有限の実行検査だけから一般命題を推測したものではない。

`2+3=5` の完全な状態列は次の通りである。

| 段 | pc | R0 | R1 | R2 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 2 | 3 | 0 |
| 1 | 1 | 2 | 3 | 0 |
| 2 | 2 | 2 | 3 | 0 |
| 3 | 3 | 3 | 3 | 0 |
| 4 | 4 | 3 | 3 | 1 |
| 5 | 1 | 3 | 3 | 1 |
| 6 | 2 | 3 | 3 | 1 |
| 7 | 3 | 4 | 3 | 1 |
| 8 | 4 | 4 | 3 | 2 |
| 9 | 1 | 4 | 3 | 2 |
| 10 | 2 | 4 | 3 | 2 |
| 11 | 3 | 5 | 3 | 2 |
| 12 | 4 | 5 | 3 | 3 |
| 13 | 1 | 5 | 3 | 3 |
| 14 | 5 | 5 | 3 | 3 |

### 1.3 実行器と検査器の役割

実行器 `runRegisterMachine` は命令を順次実行して状態列を作る。検査器 `verifyRegisterTrace` は実行器を呼び出さず、提出された隣接状態について各レジスタの更新式と次の命令位置を調べる。共通に用いるのは入力形式・型・範囲の検査である。

検査対象は、命令列、初期入力、最初の状態、全遷移、正常な終状態、出力レジスタ、復号値である。外から要求された命令列・入力・出力も指定して照合できる。最終出力が同じでも入力をすり替えた証跡は、元の要求の証跡として受理しない。

指定手数で中断した実行は `step-limit` と記録し、正常終了の証明として拒否する。最後の状態を `halted` と書き換えるだけでも、実際の命令が `halt` でなければ拒否する。実装上限はレジスタ64個、命令10000個、自然数1000桁、一実行100000遷移であり、数学的に許す有限表示の上限を定義したものではない。

## 2. 仮定された構造の法則から、式変形を検査する

### 2.1 何を機械検査しているか

新しい限定検査器 `verifySymbolicProof` は二種類の理論だけを受け付ける。一つは加法の結合律・右逆元則・右単位則、もう一つは合成の結合律・境界に対応する左右の恒等則である。式変形の規則表は検査器側に固定し、証跡から任意の法則を追加できない。

証跡には開始式、終了式、各段の規則名、代入、向き、部分式の位置、変形前後の式、明示した仮定を保存する。検査器は全てを照合する。位置は根が `[]`、引数を左から数えて `[0]`, `[1]`, … とする。これは文字列の何文字目かを指定する方式ではなく、構文木の道筋である。

規則に用いる群や圏の法則は、**その構造を扱うという仮定**である。この検査の成功を、現在構成したFεについての一般的な体法則の機械証明とは呼ばない。Fεでこれらの法則が成り立つ根拠は、現稿の構成とその証明にある。この切り分けにより、例示された抽象構造の公理を、数の内部構成の出発点に移す必要はない。

### 2.2 加法による付加と取消しの三手

`c,u` を加法群の任意の項とする。可換律はこの導出に用いない。

| 段 | 変形前 | 規則・向き・位置 | 変形後 |
| --- | --- | --- | --- |
| 1 | `(c+u)+(-u)` | 結合律・順方向・`[]` | `c+(u+(-u))` |
| 2 | `c+(u+(-u))` | 右逆元則・順方向・`[1]` | `c+0` |
| 3 | `c+0` | 右単位則・順方向・`[]` | `c` |

第一段の代入は `a↦c,b↦u,c↦-u`、第二段は `a↦u`、第三段は `a↦c` である。式に現れる原子名と規則の模式変数を、それぞれ異なる欄で保持する。

この恒等式から、`x+u=y+u` の両辺に `-u` を加えれば `x=y` を得る。保存した三手の直接の結論は `(c+u)+(-u)=c` であり、一般の消去推論を別の証跡として保存したと主張するものではない。

### 2.3 境界付き射の逆射一意性を示す五手

恒等射の名前 `eA,eB` を宣言し、射の境界を

$$
f:e_A\longrightarrow e_B,\qquad g,h:e_B\longrightarrow e_A
$$

とする。`eA,eB` は別種の対象を内部に追加する記号ではなく、恒等射として境界を指定する名前である。仮定は

$$
g\circ f=e_A,\qquad f\circ h=e_B
$$

の二つだけである。

| 段 | 変形前 | 規則・向き・位置 | 変形後 |
| --- | --- | --- | --- |
| 1 | `g` | 右恒等則・逆方向・`[]` | `g∘eB` |
| 2 | `g∘eB` | 仮定 `f∘h=eB`・逆方向・`[1]` | `g∘(f∘h)` |
| 3 | `g∘(f∘h)` | 結合律・逆方向・`[]` | `(g∘f)∘h` |
| 4 | `(g∘f)∘h` | 仮定 `g∘f=eA`・順方向・`[0]` | `eA∘h` |
| 5 | `eA∘h` | 左恒等則・順方向・`[]` | `h` |

射 `v∘u` の境界は、`u` の終境界と `v` の始境界が一致するときだけ作れる。検査器はこの条件を各部分式について再計算する。恒等則で挿入する恒等射も、代入された射の境界から求める。証跡に書かれた境界ラベルを無条件に信用したり、合成不可能な式に結合律を使ったりしない。

二つの仮定を使う証明は、その仮定の下での結論である。`verifyModelExtensionBundle` は配布例の仮定・境界・主張を固定したものと照合するため、別の仮定を足した条件付き証明を、この実例の証明へすり替えることも拒否する。

## 3. 計算モデルを変えるときの保存条件

λ計算とレジスタ機械では、構文も一手の意味も手数も異なる。自然数への復号値が一致する有限例は、計算証跡をβ簡約だけに限定しなくてよいことを示す。`Add Two Three` のλ実行と§1のレジスタ実行を自然数へ復号すると、いずれも5になる。この二例の一致だけで全てのプログラムの翻訳を証明したことにはならない。

一般の翻訳を導入する際は、次の条件を個別に証明する。元のモデルをS、移し先をTとし、状態間の対応条件を `R(s,t)` と書く。

1. **入力。** 同じ許された入力の二つの初期状態が `R` を満たす。入力の型・パラメータ・固定した定義環境も対応する。
2. **一段。** `R(s,t)` が成り立ち、Sの一段が `s→s'` なら、Tで `t` から有限個かつ一個以上の正当な遷移を行って `t'` に至り、`R(s',t')` が成り立つ。その有限部分証跡を生成できる。
3. **終状態と復号。** Sの正常な終状態に対応するTの状態は、有限の終了処理の後に正常な終状態になり、両者の出力を所定の型へ復号した結果が一致する。中断や不適格入力を正常な値へ置き換えない。
4. **証跡の検査。** 各翻訳部分と終了処理はTの検査器の規則に適合する。隣接部分の境界状態が一致し、連結した証跡について、初期入力・全遷移・終状態・要求出力の検査が受理することを示す。

**命題2（有限証跡の条件付き保存）。** 上の条件を満たす翻訳は、Sの正常終了する有限証跡を、同じ復号値を持ちTで受理される有限証跡へ移す。

**証明。** Sの証跡長に関する帰納法を用いる。長さ零では入力条件によって対応する初期状態を得る。一段延長したときは条件2の有限部分証跡を連結する。部分証跡の終端と次の始端は同じ対応状態であり、条件4によって各遷移の検査が保存される。元の終状態に到達した後は条件3の有限終了処理を付ける。有限列を有限回連結した結果は有限列であり、復号の一致と終了検査は条件3・4による。□

この命題は手書きの条件付き定理である。本版は一般のλ項からこのレジスタ機械への翻訳器も、その正しさの機械証明も提供しない。また一方向の有限証跡保存だけでは、任意の発散や全ての相互翻訳の性質は結論しない。一段を一個以上に移す条件は対応する進行を明確にするための十分条件であり、零手を含む最適化では別途進行条件を設ける。

## 4. 生成ラベルを整数だけ平行移動する

これは数列生成ラベルと区間生成ラベルに共通して適用できる追加例であり、本節の一般証明は手書きである。

基本の生成ラベル `P` と整数 `k` の対 `(P,k)` を**平行移動を保持する生成ラベル**とする。数列型では入力 `n` に対して `P(n)+k` を返す。区間型では入力精度 `p` に対して、`P(p)=[l_p,u_p]` から `[l_p+k,u_p+k]` を返す。整数は有理数への既定の埋込みを通して加える。

区間型では幅が `u_p-l_p` のままで、入れ子性や精度保証も保たれる。元の応答が有限回で停止すれば、有限の有理加算を二回付けるだけなので移動後の応答も停止する。数列型でも、付加する有理加算一回が有限で終わる。

整数 `s` に対して `T_s(P,k)=(P,k+s)` と置く。入れ子のラベルを作る際は、元の基本ラベル `P` と一つの正規化した整数にまとめる。この規約と整数の法則から

$$
T_0=\mathrm{id},\qquad T_t\circ T_s=T_{s+t},\qquad T_{-s}\circ T_s=\mathrm{id}
$$

を得る。これは整数の加法群の作用を、実際の生成ラベル操作で示す例である。ここで `k` は値の平行移動量であり、自然数入力を `n+k` に変更する段移動ではない。負整数でも有効な入力を失わない。またFεの無限小方向の移動とも、追加の対応を定めるまでは別の操作である。

さらに移動を射として、`τ(P,k;s)` の始境界をラベル `(P,k)` の恒等射、終境界を `(P,k+s)` の恒等射とする。境界が一致する場合に

$$
\tau(P,k+s;t)\circ\tau(P,k;s)=\tau(P,k;s+t)
$$

と定義すれば、結合律は整数の結合律、恒等射は移動量零、逆射は `τ(P,k+s;-s)` で得られる。すべての射が逆射を持つ圏の具体例になる。異なる基本ラベルが偶然同じ値を表す場合でも、その同値を自動判定してラベルをまとめる操作はこの構成に要らない。

## 5. 公開APIと検査範囲

```js
import {
  additionProgram, runRegisterMachine, verifyRegisterTrace,
  verifySymbolicProof, buildModelExtensionBundle, verifyModelExtensionBundle,
} from '../verification/model-extensions.mjs';

const trace = runRegisterMachine(additionProgram(), ['2', '3', '0']);
verifyRegisterTrace(trace, {
  program: additionProgram(), initial: ['2', '3', '0'],
  outputRegister: 0, output: '5',
});
const bundle = buildModelExtensionBundle();
const report = verifyModelExtensionBundle(JSON.parse(JSON.stringify(bundle)));
```

検査関数は成功時に `ok: true` を含む報告を返し、不適格な入力・証跡・主張を拒否するときは例外を送出する。証拠束の形式名は `f-model/extensions/1` であり、次を含む。

| 証拠 | 直接検査される主張 |
| --- | --- |
| `register-add-2-3` | 指定した加算プログラムで入力 `(2,3,0)` から14遷移で5を返す |
| `register-add-7-0` | 作業レジスタの初期値91を零化し、入力7と0から7を返す |
| `register-add-large-2` | `9007199254740993+2` を丸めず `9007199254740995` と返す |
| `group-cancellation` | 明示した群法則の下で `(c+u)+(-u)=c` を3手で導く |
| `arrow-inverse-uniqueness` | 明示した境界・圏法則・二つの逆関係の仮定から `g=h` を5手で導く |

独立したテスト14件では、二入力をそれぞれ0〜7とした加算、五命令、100桁を越える加算、誤った更新・分岐・入力・出力、終了していない証跡、終了後の余分な遷移、構文の型と範囲、規則名・代入・向き・位置・仮定・射の境界の改変を調べる。検査器自身の全面的な健全性の機械証明、任意のプログラムの停止判定、本稿全文の形式化はこの報告に含めない。

再検査はプロジェクトのルートで `node verification/model-extensions-tests.mjs` を実行する。必要なライブラリの追加インストールはない。
