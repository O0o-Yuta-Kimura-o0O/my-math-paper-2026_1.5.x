# 本稿の概念を基本記号で表す — v1.5.8

本版は「f生成体系」の用語を採用する。Mは「M多項式」、F上のCεとHεは「生成複素数」「生成四元数」、数列を指定する有限記述は「数列生成ラベル」、精度要求に有理区間を返す手続きを指定する有限記述は「区間生成ラベル」、検査に用いる処理履歴は「計算証跡」と呼ぶ。生成ラベルは生成規則・パラメータとの対応を持ち、実行する生成器とその出力を区別する。Fの「〇〇実数」という新名称は検討中であり、この版ではFまたは有限有理式数と表記する。

本版の[付録：fだけでたどる本論文](../appendices/A_New_Foundation_of_Mathematics_ja_v1.5.8_f_only.md)では、ここで説明に使う対の記号も `f(左右の内容)` に置き換える。この文書は、その付録を読むための中間表記と詳細説明を与える。

木村祐太の原案に沿った概念記号列の仕様と読み方。2026年9月27日改訂。

**必要な数と演算を、共通の有限構成から増やす。計算開始前に型を指定し、全入力と結果をその型に固定する。** 本版ではFの対から型Tを構成し、σ²=2を満たす有限の値を扱う。近似値を求めるときは別の操作を要求する。生成器・厳密演算・対応証明を必須の一組へ統合するラベル案は採用しない。

**本版では M を、有理係数の有限多項式とする。F は M 同士の分数である。** 旧版の `(整数段数, 有理数)` は、関係子ラベルの表示 L として残す。本版ではG(q,b)からΦでLへ導入する規則を指定し、実行記録の係数bとラベルの整数kを分ける。生成複素数は原案の二行二列の表示を保ち、生成四元数はその生成複素数二つの対で表す。

本稿に現れる数、有限列、プログラム、命題、推論規則、証明木、計算履歴は、下記の形成規則に従って `f`、丸括弧、カンマへ符号化できる。空白と改行は読みやすさのためだけに使う。ただし、記号列が表す内容を読む規則と、実行・証明の規則も明示しなければならない。

## 1. 基本記号列と型

説明用に `S` を「既に作った基本記号列」のメタ変数とする。後述する数の型Tとは区別する。

```text
基底       f()
一引数形   f(S)
対         (S, S)
```

この三つだけを有限回使う。それ以外の文字は、下の仕様では説明用の略記である。`()` 単独や三要素の組を新しい構成子にしない。三要素以上は二つ組へ展開する。

一引数形と対と基底は先頭の記号と括弧の構造で区別できる。解析器は全入力を読み切り、余分なトークン、片側だけの括弧、引数不足を拒否する。

**型が固定された数の表示**では型タグを付けない。原案の自然数・整数・有理数の表示をそのまま保つ。型の異なる値を同じ欄に保存する場合は、後述の `(型符号, 値)` を使う。これにより、自然数の零と空列が同じ `f()` であっても混同しない。

一つの計算では、その開始前に型AとA上の演算を指定する。全入力をAの形成条件で検査し、結果もAとして読む。埋込みが必要なら、あらかじめ明示してAの表示へ変換する。計算途中で型を推論したり、結果を見て型を自動昇格させたりはしない。型・演算・入力・結果を記録にまとめる例は§13.6に示す。

ここで同じ型に固定するのは数の算術計算である。形成条件を検査する処理は入力の数型を変更せず、別に指定した真偽型へ検査結果を返す。

自然数Nの構文検査 `NatForm` は、fのみ表記で `f()` を真、`f(t)` を `NatForm(t)`、二子の `f(tu)` を偽とする。これは開始前に指定したNに対する形成検査であり、任意の入力の型を発見する手続きではない。有限木の解析と、このNの形成条件を確かめることも区別する。§13.7では、この再帰処理自体を有限木で保存し、実行して照合する。

### 自然数と有限列

```text
N(0)     := f()
N(n+1)   := f(N(n))

List()          := f()
List(x, 残り)   := (x, List(残り))
```

例えば三要素の列は `(x, (y, (z, f())))` となる。`N`、`List`、`n+1` はこの定義を説明する名前であり、完成した記号列に残らない。

固定長の対 `(x,y)` と、二要素の列 `(x,(y,f()))` は異なる表示である。用途ごとの形を以下で指定する。

### 有限種類の構成子を区別する

```text
Node(タグ番号; 引数列) := (N(タグ番号), List(引数列))
```

同じ構文の中の構成子には重ならない自然数番号を付ける。タグも反復した `f` へ展開でき、新しい基本記号ではない。異なる構文族で同じ番号を使う場合は、外側の型が族を決める。

例えばタグ一、引数なしは `(f(f()), f())` となる。タグ零、引数に自然数一だけを持つ形は `(f(), (f(f()), f()))` である。

## 2. 自然数、符号、整数、有理数

| 概念 | 構造 | 形成・正規化の条件 |
|---|---|---|
| 自然数 | `N(n)` | 零と一段追加だけ |
| 符号 | `N(0)` または `N(1)` | 零が非負側、一が負側 |
| 整数 | `(符号, N(絶対値))` | 大きさ零の符号は必ず零 |
| 有理数 | `(整数分子, 整数分母)` | 分母は正、既約、零は0/1 |
| 真偽値のデータ | 偽=`N(0)`、真=`N(1)` | Church真偽値のプログラムとは別の型 |
| 比較結果 | 整数の−1、0、1 | 小・等・大。符号だけとは型が異なる |
| 値なし／値あり | `Node(0;)`／`Node(1;値)` | 次数や部分演算の結果など |
| 成功／失敗 | `Node(0;値)`／`Node(1;理由の文字列)` | 失敗を数の零に置換しない |

有理数の分母を正の自然数で保持する既存算術実装と、ここで正符号付き整数を使う表示は相互変換できる。分母の正符号を付ける／取り除く操作であり、分母条件は変わらない。

加減乗除、比較、絶対値、冪、商と余り、gcd、Bezout係数は、それぞれ**値の型ではなく操作**である。操作のプログラム・呼出式・実行履歴は第6・7・9節の形式で記号化する。例えば有理数加算の出力は再びこの表の有理数表示となる。

## 3. M多項式とその分数 F

### Mの表示

```text
M := 有理数の有限係数列
```

係数は定数項から並べる。説明用の式 `a₀+a₁ε+…+a_dε^d` の表示は `List(a₀,a₁,…,a_d)` である。次数は位置から分かるので、係数列にεや指数の文字は入れない。零多項式は `f()`。最高次数側の零係数を除き、各係数を有理数の正規形にする。

これは単一の固定次数ではない。各Mは有限列だが、形成規則には次数の固定上限を置かない。

### 原案の関係子との対応

関係子ラベルを `L := (整数k, 有理数q)` と呼び、Mの係数列 `List(q,k/1)` へ移す。零係数の末尾を除く。ここで `q#` は `q+ε`、`q♭` は `q−ε` の略記である。生成記録 `G(q,b)` からは、明示した規則 `Φ(G(q,b))=(2sgn(b),q)` で導入する。b>0なら導入先は `q##` であって `q#` ではない。

Mには `ε/2` もあるため、M全体では `0` と `0#` は隣接しない。整数段数の鎖に限定したLの隣接と区別する。Φは実行記録からラベルへの導入規則であり、点ごとの加法を保存する商写像ではない。`0##+0##=0####` では結果のk=4を保持する。詳細な構造と有限検査は§14に示す。

### Fの表示

```text
F := (Mの分子, Mの分母)
```

分母は零多項式以外。交差積が等しい表示を同じ値とし、正規表示では多項式gcdで約分し、分母の最高次係数を一にする。零は `(零多項式, 一多項式)` とする。

| 概念 | 基本データとして持つ内容 |
|---|---|
| Mの次数 | 値なし、または自然数。零の次数を返す実装の−1との対応を明示 |
| Mの最小非零次数 | 値なし、または自然数 |
| Fの最小次数差 | 零なら値なし、それ以外は整数 |
| 多項式除算の結果 | `(商M, 余りM)` |
| Euclid処理 | `List(被除数M, 除数M, 商M, 余りM)` を各段として並べた列 |
| 約分の証拠 | gcd、分子商、分母商、各除算履歴 |
| モニック化の証拠 | 正規化前の最高次係数と、その逆数の有理数 |
| Fの比較 | 差の分子と分母の最小非零係数、次数、比較結果 |
| 有限部分O | Fの表示に `次数差≥0 または零` という形成条件を加えたもの |
| 標準部st | Oを入力として有理数を返す操作。全F上の操作にはしない |

Mの多項式に通常の引数を与える評価と、εを正の微小方向として読むFの順序は別の操作である。係数列が同じでも、何を計算するかを操作側で指定する。

## 4. 生成複素数と生成四元数

以下の `a,b,c,d` はFを表す説明用の名前である。

```text
C(a,b) := ((a, −b), (b,a))
H(a,b,c,d) := (C(a,b), C(c,d))
```

負号は完成した記号列に残さない。Fの符号反転を実行し、その結果を基本記号へ展開する。複素数は任意の四成分行列ではなく、上記の成分関係を満たすものに限る。

四元数の二成分を `z,w` として `z+w j` と読む。乗法を `(z,w)(u,v)=(zu−w conjugate(v), zv+w conjugate(u))` と定める。単なる成分ごとの掛け算ではない。複素共役は `C(a,−b)`、四元数共役は `(conjugate(z),−w)`。ノルム平方はFの `a²+b²+c²+d²` であり、非零ならその逆数を用いて四元数の逆元を作る。

複素数・四元数の形成と表示の検査は符号化器に実装する。四元数の一般代数法則を既存のNat/Seq一般命題の証明検査に含めた、とはしない。

### Fの有限対T

```text
Tの値       := (a,b)          a,bはF
σ           := (0,1)
Tの0,1,2,−1 := (0,0),(1,0),(2,0),(−1,0)
Tでの積     := (a,b)(c,d) = (ac+2bd,ad+bc)
```

説明用の `a+bσ` に対し、σの文字は完成した記号列に残らない。F二つの対を、各Fの多項式比・有理係数・符号・自然数へ展開する。例えば `(1,1)(1,−1)=(−1,0)` と `σ²=(2,0)` は、型をTに固定した有限の成分計算である。σ/2も `(0,1/2)` として表す。Tは独立に加える有限対の拡張例であり、近似の実行や区間生成ラベルの添付を値の形成条件にしない。一般法則とFからの埋込みは本文§8.10に記す。

## 5. 文字、名前、型、任意の有限レコード

### 文字と名前

変数名、操作名、規則名、エラー理由などは、文字列をUTF-8のバイト列にし、各バイトを自然数として `List(N(b₀),N(b₁),…)` にする。これは保存のための明示的な規約であり、数学の新公理ではない。不正なUTF-8は拒否する。

名前の参照だけを記録する場合は、その名前が指す定義表も必要である。`Add`という名前の符号だけを、加算アルゴリズムの完全な定義とは呼ばない。

### 型構文

型も `Node` を使う。今回の例集の番号は以下の通り。

| タグ | 型 | 引数 |
|---|---|---|
| 0〜13 | N, Z, Q, M, F, C, H, Bool, Text, Arrow, Lambda, Proposition, Proof, Unit | なし |
| 14 | List | 要素型 |
| 15 | Pair | 左型、右型 |
| 16 | Option | 値型 |
| 17 | Function | 入力型、出力型 |
| 18 | Ordering | なし |
| 19 | Interval | なし。有理端点 |
| 20 | Generator | 入力型、出力型 |
| 21 | QRep | なし。正の非零整数分母を持ち、未約分を許す補助表示 |
| 22 | Result | 成功値の型 |
| 23 | T | なし。F二つの対とσ²=2の乗法 |
| 21 | QRep | なし。正の非零分母を持つ未約分の整数対 |
| 22 | Result | 成功値の型 |

型構文を保存できることと、その型に合うかを検査できることは別である。任意のプログラムの停止や出力保証を、型名を書くだけで得ることはできない。

### 既存JSON証拠を欠落なく保存する規約

既存の証拠ファイルにある全欄は、次の汎用形式でも保存できる。この形式は直接の数表示とは異なる、相互変換用の外装である。

```text
J(value) := (N(JSON種類タグ), payload)
```

| タグ | 種類 | payload |
|---|---|---|
| 0 | null | f() |
| 1 | false | f() |
| 2 | true | f() |
| 3 | 有限JSON数 | 正規JSON数文字列のText。−0は拒否 |
| 4 | 文字列 | Text |
| 5 | 配列 | List(J(各要素)) |
| 6 | レコード | List((Text(キー),J(値)))。キーを昇順に整列 |

JSON数の有限精度と、数学上の自然数・有理数の精度を混同しない。既存の大きな整数や有理数は元ファイルでも文字列になっており、その内容を保持する。JSONの空白とキーの元の印刷順は保持対象外であるが、全キーと値は保持する。重複キーや非正規の順序は復号時に拒否する。

## 6. λ項、関数、再帰、操作

### λ構文そのものの基本記号化

束縛変数は、直近の束縛からの距離を零始まりの自然数で表す。自由変数名はTextを使う。

| λ構文のタグ | 構成子 | 引数 |
|---|---|---|
| 0 | 束縛変数 | 距離N |
| 1 | 自由変数 | 名前Text |
| 2 | 関数適用 | 関数項、引数項 |
| 3 | λ抽象 | 本体項 |

例えば恒等関数 `λx.x` は `Node(3;Node(0;N(0)))` へ、さらに `f`・括弧・カンマだけへ展開する。束縛名を距離に変えるため、α同値な名前の変更は同じ構文になる。自由変数は名前を保持する。

例集にはインタプリタv8.0.1の**全内蔵定義**と、固定点項Yをこの構文で収録する。参照名のある定義については、全定義表も合わせて示す。基本記号列を復号して元のλ項とのα同値を検査する。これは各定義の停止性や一般数学法則の検査ではない。

### 環境、閉包、プログラム

```text
定義       := (名前Text, λ本体)
定義環境   := List(定義)
閉包       := (本体構文, 環境)
プログラム := List(言語・版, 入力型, 出力型, 本体, 定義環境)
```

有限の再帰的なプログラムは、固定点項などの有限構文として保持する。実行履歴が無限になる場合でも、その無限履歴を一つの有限列として印刷するわけではない。

数の生成に使う `f(t)` と、保存したλ項の関数適用は異なる構文である。後者はタグ二の対として表す。基本記号へ翻訳しただけの文字列が、そのまま現在のHTMLの入力言語になるわけではない。

### 数学的な呼出式

数学的な項の構文を、次のタグで記録できる。

| タグ | 項 | 引数 |
|---|---|---|
| 0 | 変数 | 束縛距離N |
| 1 | 定数値 | 型、値 |
| 2 | 操作呼出し | 操作名Text、引数項のList |

加減乗除、比較、gcd、正規化、射の合成、生成器の呼出し、微分・積分はこの最後の形で表せる。各操作の有限な定義本体は本文・実装・対応表で特定する。JavaScriptの厳密算術を純粋λの実装と呼ぶことはしない。

## 7. 命題、条件、仮定、推論、一般証明

### 命題構文

| タグ | 命題 | 引数 |
|---|---|---|
| 0 | 等式 | 型、左項、右項 |
| 1 | 狭義順序 | 型、左項、右項 |
| 2 | かつ | 左命題、右命題 |
| 3 | または | 左命題、右命題 |
| 4 | ならば | 前件、後件 |
| 5 | 偽 | なし |
| 6 | 任意の値について | 変数型、本体命題 |
| 7 | ある値について | 変数型、本体命題 |
| 8 | 名前付き述語 | 述語名Text、引数項のList |

量化子は本体内に一つの束縛を導入し、項の変数を距離で読む。否定は「命題ならば偽」、非等値は等式の否定、非狭義順序は狭義順序または等式へ展開する。真は「偽ならば偽」としても表せる。

この表は本稿の手書き命題を保存するための構文である。現在の等式検査器に一般的な論理連結子・存在量化の検査を追加したものではない。述語の定義表、変数の型、束縛範囲を伴わない式を、意味の確定した命題とみなさない。

### 証明構文

```text
仮定文脈 := List(命題)
判断     := (仮定文脈, 結論命題)
証明節点 := List(規則番号, 判断, 規則固有データ, 前提証明のList)
証明     := (規則体系と版, 証明節点)
```

反射・対称・推移・合同・代入・仮定使用・自然数帰納・列帰納は有限個の規則名に番号を付けられる。規則固有データには変換位置、代入対応、帰納変数、基底証明、段階証明などを保持する。

一般命題は、自由変数と仮定を含む有限構文として表す。例えば加法の結合律は、変数三つを量化した一つの命題であり、全ての数の組の計算表ではない。帰納証明も基底と段階の有限な木である。帰納変数の新鮮性、仮定のスコープ、型の一致は検査側の条件であり、番号を書くだけでは保証されない。

例集では説明用の証明節点を作るほか、**既存のNat/Seq一般命題を含む実際の証明JSON全体**も基本記号へ変換する。それを復号し、元の `checkBundle` で再検査する。既存の証明形式をこの説明用の別形式へ翻訳して新しい証明検査器を作った、とは主張しない。

## 8. 代数構造と射のみの圏

半群・モノイド・群・環・体は、新しい種類の原子的な数ではない。対象となる型、操作の定義、単位や逆元、法則とその証拠をまとめた仕様として表す。

```text
代数構造 := List(対象型, 操作定義のList, 特別な値のList, 法則と証拠のList)
```

半環の自然数、環の整数とM、順序体のQとF、複素数、四元数について、演算と法則の種類を変えて同じ構造を使える。四元数に乗法の可換律を含めない。任意の型にこのレコードを書けば法則が成立する、という意味ではない。

射のみの圏では、有限の状態表示と変換履歴から射を構成する。

```text
変換段     := List(規則, 位置, 変換前, 変換後, 補助証拠)
射         := (初期状態, List(変換段))
恒等射     := (状態, f())
始域を表す射 := (初期状態, f())
終域を表す射 := (最終状態, f())
```

合成は終点と始点が一致するときだけ、段の列を連結して作る。各段の妥当性とつながりを検査する。状態は恒等射を構成するためのデータであり、対象を別の原始構成子として導入しない。異なる履歴が同じ端点に到達しても、履歴の等値では別の射である。

恒等則・結合則は、命題と一般証明の形式で記録する。本稿で構成した有限履歴の圏が対象であり、任意の巨大な圏の全射を有限列に収録できると主張するものではない。

## 9. 計算証跡と終了状態

| 概念 | 保持する有限データ |
|---|---|
| 構文一致 | 二つの構文木と比較結果 |
| α同値 | 束縛距離に変換した二つの木。自由名は保持 |
| β一段 | 簡約前項、位置、簡約後項 |
| δ一段 | 展開前項、定義環境、参照名、位置、展開後項 |

## 10. 数列生成ラベル、区間生成ラベル、基本解析

### 有限要求を受ける生成器

```text
生成器の仕様 := List(プログラム, 入力型, 出力型, 保証命題)
保証付き生成器 := (生成器の仕様, 保証命題の証明)
一回の応答 := List(生成器の識別, 入力, 出力, 有限計算証拠)
```

保証の証明がまだない段階では「仕様」として保存し、保証付きとは呼ばない。プログラムの符号は一つでも、各要求への応答は別の有限計算である。

| 概念 | 表示・処理に必要な内容 |
|---|---|
| G(q,b)=qlim(q,b) | 有理数q,bと、入力nに `q+b/(n+1)` を返す定義。bを保持する実行記録 |
| 共通部分列 | 比b/c=r/s、有限パラメータt、添字rt−1とst−1、共通の有理出力 |
| 関係子ラベルへの導入Φ | 出力は `(整数2sgn(b), 有理数q)`。bを捨てても演算結果の整数kは保存する |
| 精度要求p | 自然数p |
| 許容誤差 | 有理数 `1/2^p`。pとは別の値 |
| 有理区間 | `(下端Q, 上端Q)`。下端≤上端 |
| 区間幅・中点 | 有理数の演算結果 |
| 入れ子条件 | 端点間の非狭義順序命題 |
| √2の状態 | 段数N、下端Q、上端Q |
| √2の一段 | 中点、その平方と2との比較、新区間 |
| √2の応答保証 | 平方による挟み込み、幅、有限段数の証明 |
| Leibnizの状態 | 段数m、下端Q、上端Q |
| 交代級数の一段 | 符号付き有理項と新端点 |
| Πの応答保証 | 入れ子、幅 `4/(4m+3)`、精度に必要な有限段数 |
| 区間四則 | 入力区間、候補端点、有理演算、最小値・最大値 |
| 区間除算の条件 | 分母区間が零を含まないこと |
| 多項式関数 | Mの係数列と、有理引数で評価する定義 |
| 連続性の応答 | 係数、半径R、要求p、M_R、δ、入力二点、誤差境界 |
| 形式微分 | 係数列を `a₁,2a₂,…` へ変換する有限処理 |
| 差商 | x、非零h、関数値二つ、差商、導関数値 |
| 導関数の誤差 | 係数C_R、`C_R abs(h)`、その不等式証拠 |
| 形式原始関数 | 定数項を指定し、各係数を次数で割ったM |
| 有理端点の形式積分 | 係数列、端点a,b、原始関数の端点値と差 |

添字、精度、半径、誤差係数、端点、各段の番号は、すべて既に定めた自然数・整数・有理数・列の表示へ戻る。`qlim`や√2などの名前は、プログラムと定義表を参照する名前である。

ここでのΠの有限算術証拠は、それだけで幾何学的円周率との同一性を証明しない。生成器の全出力を一つのFの元と同一視もしない。任意の実数・任意の関数が有限のプログラムを持つという主張は、本稿に含めない。

## 11. なぜ有限の概念構文を基本記号へ戻せるか

各構文を有限個の構成子と有限の引数列で定める。構成子番号は自然数、引数の並びは対の列で表す。構成子の子に同じ変換を繰り返す。

基底の符号には一意な読み方がある。複合構文ではタグが構成子を決め、その構成子の引数の個数・型に従って各子を復号する。子の復号結果が元に戻るという帰納仮定から、親も元に戻る。したがって、形成条件を満たす有限構文について `decode(encode(x))=x` が構造帰納で従う。

正規化を伴う数について右辺は正規化した値である。例えば `q(2,4)` で先に有理数を1/2へ正規化してから符号化する。今回の有理数コーデックは、文字列 `2/4` などの未正規化入力を直接渡すと拒否する。一方、既存JSON証拠の外装では値・キーを失わない形で保存する。両者の役割を区別する。

この説明に必要なのは、有限構文、構成子の区別、解析と復号の規則、構造帰納である。記号の種類を減らすことによって、これらの規則まで不要になるわけではない。

## 12. 実装と再現

実装は [concept-codec.mjs](../verification/concept-codec.mjs)。厳密な構文解析・印刷、自然数から四元数、Text、汎用JSONの符号化と復号を提供する。例の定義とλ構文の変換は [生成・検査スクリプト](../scripts/generate-concepts.mjs) にある。

```sh
node scripts/generate-concepts.mjs
node scripts/generate-concepts.mjs --check
node verification/concept-codec-tests.mjs
```

最初のコマンドは例集と基本記号ファイルを作る。`--check` は保存済みの内容を読み、再生成した構文との一致・復号・既存証拠の再検査を行う。公開用コピーでは検査だけを行えばよい。

巨大な自然数を一つの単項列で印刷すると出力が大きくなるため、実装は有限の資源上限を持つ。これは数学上の形成規則の上限ではない。詳細な既定値はコーデックの `CODEC_LIMITS` とコード内説明を参照する。

本版の追加検査は表示を失わずに行き来できることを確かめるものであり、全演算を新しい基本記号インタプリタへ移植したものではない。既存の一般証明と個別計算の検査は、復号後にそれぞれの規則体系で行う。

## 13. 既存版から引き継ぐ概念の構造

本節は本文§6.4、§8.9の条件付き最小性、§9.2・9.6–9.9、§10のモデル・λ算術拡張を補う。数の基底、M、F、生成複素数・生成四元数の表示は変えない。以下の名前は各欄の意味を伝える略記であり、最終的な保存には既存の自然数、対、列、Text、JSON外装Jを用いる。具体例・実証跡は[最新版の一覧](../verification/concept-symbols-v1.5.8/manifest.json)で照合する。

### 13.1 規則・契約・証拠を保持するラベル

```text
生成ラベル     := List(規則と版, パラメータ, 入出力型と保証, 保証の証拠)
証拠の状態     := List(手書き参照・保存済み証明木・検査済み証明木の区別, 根拠)
個別応答       := List(ラベル, 要求, 出力, 具体的な有限証跡)
未充足の条件   := List(必要な命題, 現在得られている証拠)
```

本文の仕様を有限データとして保存できることと、任意の証明文を検査器が受理することを区別する。参照するだけの手書き証明に「機械検査済み」という状態を付けない。現在の有限DSLは既知の規則とパラメータを受け付け、任意の関数文字列を実行しない。

この記録は生成器の応答保証を扱う場合の形式であり、全ての数を統一して覆う必須ラベルではない。Tの厳密な値と演算は、この生成ラベルへ統合せずに定義する。

| 新概念 | 基本型へ戻した保持内容 | 条件・証明状態 |
| --- | --- | --- |
| 応答整合 | 二つのラベル、任意二精度の端点条件、その証明 | 特定二精度の交わりだけで全称的整合を認定しない |
| 零分離 | 要求精度N、応答区間(Q,Q)、正の距離Q、応答証跡 | 全区間が零の片側にあることを比較で検査 |
| `zero` / `unknown` / `separated` | 異なるタグまたはTextと、零・値なし・正の距離 | `unknown`を零に変換しない。構造例の`nonzero`は、具体証跡の`separated`に対応する非零情報 |
| 和・積・逆数の合成ラベル | 操作名、子ラベル、必要なら分離精度 | 生成器の有限木であり、新しい数の原子ではない |
| 精度配分 | 外部要求p、内部要求r、絶対値上界、感度、幅の評価 | 積の大きさと分母の零分離に応じる有理計算 |
| 条件付き最小性 | 対応先の順序体仕様、Qの写像、正の微小元δ、保存条件、評価写像 | Fの普遍的な唯一解釈という主張ではない。一般保証は手書き |

### 13.2 区間生成の新しい状態と遷移

```text
Newton状態 := List(段数N, 下端Q, 上端Q, 積Q, 下端平方Q, 上端平方Q, 幅Q)
Newton段   := List(前状態, 新状態, 前幅Q, 端点和Q, 幅再帰Q, 四分の一境界Q)
交代項列   := List(family, 有理・自然数パラメータ)
交代和段   := List(添字N, 項Q, 符号付き部分和Q, 区間, 幅Q)
誤差率     := List(有限の自然数プログラム, 保証命題, 保証の証明)
有限窓     := List(精度N, 標本添字N, 標本Q, 誤差Q, 下端Q, 上端Q)
有限共通部 := List(窓のList, 下端の最大Q, 上端の最小Q, 共通標本Q)
```

Newtonの $l=2/u$、$u'=(u+l)/2$、幅の再帰は、それぞれQの呼出式としても表せる。記録にある平方や幅の欄は再計算して検査する。二分法との応答整合は、平方の挟み込みと非負性から手書きで全称的に証明する。実証跡は特定の要求に対する照合を保持する。

交代項列の実装familyは非負の幾何列と逆一次列に限定する。一般定理の任意の適格な項列と、この実装上の受理範囲を区別する。誤差率付き列から区間への実装では、幾何ずれ列と添字への定数加算による率を用いる。異なる率・精度の照合には、両方の必要添字以上の同じ標本と、それを含む端点を保存する。

有理精度 $2^{-p}$ とF全精度の正の要求値δは型が異なる。後者はFの表示を用いる。逆数の差商と有限長方形和の誤差式は有限命題構文へ戻せるが、その一般証明の機械検査を新しい区間証跡に含めない。F内で「どんな有理誤差よりも小さいなら零」と推論する規則も追加しない。

### 13.3 符号・大きさによるλ整数と有理補助表示

[λ算術ノート](lambda-arithmetic-v1.5.8.md)の全定義はλ項の構文木として収録する。整数 `Pair s n` でsはChurch自然数の0または1、nは大きさである。これは本稿の整数データとの対応を持つ実行表示であり、データの直接表示 `f(符号 大きさ)` と文字列まで同じではない。

| 概念 | 保持するもの | 区別する条件 |
| --- | --- | --- |
| ZMake、ZNeg、ZAdd、ZSub、ZMul、ZEq、ZLeq | λ本体と全参照定義環境 | 型付き入力の上での演算。零の符号は非負へ正規化 |
| 差表示との往復 | ZFromDiffとZToDiffのλ本体、入力、出力、証跡 | 旧整数の差表示を現在の基底整数へ変更するものではない |
| QRep | 正の非零整数分母を持つ整数二つの対 | 未約分も許す補助表示。既約な本文Qとは別 |
| 正規化写像ν | QRepからQへの処理名と既存の正規化定義 | λ内のgcd・既約化を実装済みとしない |
| QRepの四則・比較 | λ本体、分母条件、成功または失敗 | Qへの演算保存は本文・ノートの手書き対応証明 |
| ResultOk / ResultErr / ResultBind | 成功・失敗を選択するλ項と引数 | 数学上の失敗値とHTMLの手数上限・構文エラーを分ける |
| δ/βの変換順序 | 版、戦略名、各規則、位置、前後項、定義環境 | v8.0.1の混合左端最外と、v8.0.0のδ先行を別契約で検査 |

### 13.4 レジスタと条件付き式変形

[モデル拡張ノート](trace-extensions-v1.5.8.md)では、レジスタ機械の命令を有限タグと引数列として表す。

```text
機械状態 := (命令位置N, レジスタ値NのList)
命令     := Node(命令タグ; レジスタ番号や移動先のN)
プログラム := 命令のList
実行証跡 := List(命令列, 初期状態, 全状態のList, 終了状態, 出力位置, 出力N)
式変形段 := List(規則, 代入, 向き, 構文位置, 変形前項, 変形後項)
条件付き証明 := List(規則体系と版, 型と境界の文脈, 仮定, 主張, 式変形段のList)
```

命令は `zero`、`succ`、`copy`、`jeq`、`halt` の五種類。実JSONの命令名をJで保存しても、上の構造へ戻しても有限の対と自然数に尽きる。保持すべきレジスタ、範囲、分岐先、停止条件まで検査する。`step-limit`は正常停止証明ではない。

群の取消しと境界付き射の逆射一意性は、宣言した構造の法則と明示した仮定に基づく式変形である。これらをFの体法則そのものの機械証明と呼ばない。射の始終は恒等射名で示し、合成できる位置だけで規則を適用する。

平行移動を保持するラベル `(P,k)`、整数増分を持つ移動の射、その恒等・合成・逆射の式も、同じ対と整数の構文で書ける。移動量を加える亜群（groupoid）の手書き証明と、未整理の計算履歴そのものの圏は区別する。一般のモデル翻訳の仕様は初期対応、一段の有限対応、終了・復号、検査保存の有限命題として保持する。本版の特定のレジスタ計算例を、任意のλプログラムの翻訳証明へ読み替えない。

### 13.5 新証拠束と実装ソース

`proof-generators`は生成ラベル拡張の具体証跡全体、`proof-models`はレジスタの全遷移と条件付き式変形の全体を、Jによって基本構文へ変換した識別子である。復号後にはそれぞれの専用検査器を使う。実装の[generator-extensions.mjs](../verification/generator-extensions.mjs)と[model-extensions.mjs](../verification/model-extensions.mjs)も付録のソース保存対象とする。これは実行定義の全文の可逆保存であり、JS実装が純粋λ実装へ変わるという意味ではない。

構造例では `type-qrep` が `Node(21;)`、`type-result` が `Node(22;Type(QRep))`、`qrep-four-four` が未約分4/4を表す。零分類は `zero-classification-zero`、`zero-classification-nonzero`、`zero-classification-unknown` の順にタグ0、1、2とする。これらは状態の構文例であり、判定の根拠を含む実証跡は `proof-generators` に保持する。

### 13.6 固定型の記録とTの積の検査

```text
固定型の計算記録 := List(指定型, 演算名, 入力のList, 結果)
Tの型            := Node(23;)
Tの直接表示      := (Fの第一成分, Fの第二成分)
```

`t-zero`、`t-one`、`t-minus-one`、`t-two`、`t-sigma`、`t-sigma-half`、`t-one-plus-sigma`、`t-one-minus-sigma` は省略のない完全表示である。どれも型Tを外側で指定して読む。`fixed-t-product-conjugate` は `(1,1)(1,−1)=(−1,0)`、`fixed-t-product-sigma-square` は `(0,1)(0,1)=(2,0)` の全入力・結果を持つ。

生成スクリプト内の小検査は、最初に型タグ23を確認し、二つの入力と結果の全成分をFとして復号する。その後で `(ac+2bd,ad+bc)` を既存の厳密F算術によって再計算し、結果の両成分を照合する。指定型をNに差し替えた記録、Tの位置へNの一を渡した記録、σ²の結果を一へ改変した記録は拒否する。これは型Tを選ぶ手続きではなく、先に指定された型と計算式に従う具体検査である。

Tの全四則APIやλインタプリタのT組込みを追加したものではない。一般定理8.9・系8.10の手書き証明と、ここで再計算する二つの積例は区別する。数の構成と厳密演算を先に定め、近似が必要な用途だけで別の要求・誤差・算法を指定する。

### 13.7 NatFormの有限プログラム木

次の三命令だけの小さい言語を、この形成検査の表示に用いる。タグは型タグの族と別であり、外側でNatForm命令と指定して読む。

| 命令タグ | 形 | 小実行器による意味 |
|---|---|---|
| 0 | `Node(0;Bool)` | 指定した真偽値を返す |
| 1 | `Node(1;)` | 現入力の唯一の子へ、同じプログラムを再帰適用する。現入力は一子であること |
| 2 | `Node(2;零子の枝,一子の枝,二子の枝)` | 現入力の子の個数に応じて一つの枝を実行する |

```text
NatForm本体 := Node(2; Node(0;真), Node(1;), Node(0;偽))
判定記録    := List(指定型N, NatForm本体, 入力木, 真偽結果)
```

`natform-program` はこの本体を基本記号へ完全展開したもの。`natform-zero`、`natform-successor`、`natform-pair`、`natform-nested-pair` はそれぞれ `f()`、`f(f())`、`f(f()f())`、`f(f(f()f()))` に対する真・真・偽・偽の判定記録である。後二つのf表記は一種類のfだけの表記であり、中間構文では対または一子の内部にある対に対応する。

生成時と`--check`時には、保存して復号した命令木を小実行器が実際に読み、分岐と再帰を実行する。入力の一子を一段ずつ除くので、妥当な有限入力については停止する。プログラム名やソース文字列だけを保存して真偽を主張するものではない。一方、全ての型の形成条件を自動発見する機能、一般的な型推論、型の自動昇格は持たない。実行器のソースも付録の `program-concept-examples` に可逆保存する。

### 13.8 必要時の応答を近似値と誤差上界で返す

近似操作の出力は区間に限定しない。例えば有理数の対 `(q,e)` を、近似値qと非負の誤差上界eとして読み、要求精度pとともに `(N(p),(Q(q),Q(e)))` で保存できる。この組はTの厳密な数の表示とは別の応答型である。

二つの構造例はいずれもp=3、q=17/12とする。`approx-value-error-bracket` は下端2/q=24/17と上端qの平方が二を挟むことを確認し、幅e=1/204を返す。`approx-value-error-residual` はq≥1を確認し、残差からe=|q²−2|/2=1/288を計算する。どちらも有理算術でe≤1/8を再検査する。二つの誤差上界は、それぞれ異なる有限の保証方法から得られたものである。

これらの有理条件から型Tのσに対する誤差保証を結ぶ一般命題9.5は、本文の手書き証明として扱う。二つの有限例の再計算だけでその全称命題を機械証明したとはしない。算法や返答形式を選び替えても、Tの成分と厳密な乗法の定義は変更しない。


## 14. v1.5.6から引き継ぐ生成記録、共通部分列、関係子ラベル

本節の構造は[本文§6–7・§9.11](../manuscripts/A_New_Foundation_of_Mathematics_ja_v1.5.8.md)と[ラベル設計ノート](label-design-v1.5.8.md)に対応する。型を事前に指定した欄では、既存の数の対と有限列だけを使う。新しい原始記号や汎用APIは追加しない。

```text
G(q,b) の実行記録      := (Q(q), Q(b))
L(k,q) の関係子ラベル  := (Z(k), Q(q))
Φの個別適用記録       := List(Gの記録, Lの出力)
共通部分列の一標本    := List(G(q,b), G(q,c), N(r), N(s), N(t), N(n), N(m), Q(value))
Lの加算記録           := List(左L, 右L, 結果L)
拒否検査の記録        := List(Text(指定検査名), 検査対象, N(0))
```

この中のQ、Z、N、List、Text、G、L、Φなどの文字は説明用であり、すべて§1–2の規約でfの有限木へ戻る。GとLは第一成分の型も意味も違うので、型を外側で指定して読む。一般の木からどちらの型かを推論する処理は使わない。

### 14.1 係数を保つ実行と、共通部分列

実行記録G(q,b)は、入力nへ `q+b/(n+1)` を返すためにbを保持する。同じ符号の非零有理数b,cについて `b/c=r/s` と正整数r,sで表すと、正整数tに対する添字 `n=rt−1` と `m=st−1` で出力が一致する。これは任意tについて本文命題6.2が手書きで証明する。

具体例では `q=0, b=1/2, c=3/4, r=2, s=3` とする。

| t | G(0,1/2)の添字n | G(0,3/4)の添字m | 共通の出力 | 構造例ID |
|---|---|---|---|---|
| 1 | 1 | 2 | 1/4 | `relation-common-1` |
| 2 | 3 | 5 | 1/8 | `relation-common-2` |
| 3 | 5 | 8 | 1/12 | `relation-common-3` |

検査は各レコードを復号し、比、添字の式、二つの出力を有理算術で再計算する。三標本の成功を任意tの機械証明とは呼ばない。

### 14.2 bを捨てる導入と、kを保つ演算

指定する導入規則は `Φ(G(q,b))=(2sgn(b),q)` である。符号に従ってkは2、−2、0となり、正のbはq##、負のbはq♭♭、零のbはqへ導入する。実行記録とは別の出力を作るため、元の記録からbを消去する必要はない。

`relation-intro-positive-half` と `relation-intro-positive-three-quarters` は異なるbから同じL(2,0)を得る例である。負と零は `relation-intro-negative`、`relation-intro-zero` に収める。これは指定した規則の有限性とbの大きさからの独立を示す命題6.3の具体例であり、全生成器についての万能な同値判定ではない。

導入後のラベルには、Lで定義した成分加法と順序を使う。`relation-l-addition` は `L(2,0)+L(2,0)=L(4,0)` を保存する。k=4を符号だけから2へ戻さない。`relation-l-order` はFへの既存の埋込みを通して `0<0#<0##<0####` を検査し、非零のラベルと整数段数を保持する。

一方、`u=G(0,1/2)` の点ごとの和は `u+u=G(0,1)` なので、再導入すると `Φ(u+u)=L(2,0)` となる。ラベル同士を加えた `Φ(u)+Φ(u)=L(4,0)` とは異なる。この二経路を `relation-intro-not-additive` で別々に計算し、不一致を検査する。生成記録の加法をそのまま商へ降ろしたものとはしない。

近似の添字nは生成器への入力であり、関係子の整数kはラベルに保存する数値成分である。両方を自然数の「回数」という同じ欄へ混ぜない。正の導入先の##は二個という固定した表示であり、nに合わせて増える表示ではない。

### 14.3 有理精度と拒否の有限検査

`relation-rational-error` は、L(2,3/2)の有理近似として3/2を返し、p=3の要求に対して厳密な差2εが `0<2ε<1/8` を満たすことをF算術で検査する。これは命題9.6の全pの保証の一例であり、有理精度で区別できない元を厳密に等しいとはしない。σ+kεへの一般的な接続は同命題の手書き証明に残る。

三つの拒否記録は、整数欄に自然数だけを置いた不正なL、Φの虚偽結果L(4,0)、加算結果をL(2,0)へ圧縮した虚偽結果を含む。保存した候補を実際の局所検査へ渡し、拒否が発生することを確認する。N(0)という拒否予定の値を文字列として保存するだけではない。

追加構造例は19件である。各基本記号ファイルと検査結果は最新版の生成一覧で確認する。fのみ表記への変換は同じ木を保ち、英語付録もその木を共有する。一般の共通部分列・導入・順序・精度の定理は本文の手書き証明であり、有限例を符号化したことで一般定理の機械証明へ変わらない。

## 15. v1.5.7から引き継ぐ等比生成記録と循環小数の解釈

[本文付録A](../manuscripts/A_New_Foundation_of_Mathematics_ja_v1.5.8.md)で扱う等比再帰と小数表示を、以下の固定した型で保存する。Q、N、Listなどは読み方の略記であり、ファイル内では既存のfの木へ完全に戻る。

```text
H(q,b,r)           := (Q(q),(Q(b),Q(r)))       ただし0<r<1
Hの有限応答列      := List(H,List(List(N(n),Q(value)),…))
Ψの導入記録        := List(H,L(2sgn(b),q))
循環小数記録       := List(N(whole),List(prefixDigits),List(repeatDigits))
厳密値の読み       := List(循環小数記録,Q(value),L(0,value))
```

Hは `x_0=q+b`、`x_(n+1)=q+r(x_n−q)` を実行する記録である。Φを持つGの定義を変更せず、Hに対する指定規則Ψを別に設ける。Ψはnやrを関係子の個数へ変換せず、bの符号からkを2、−2、0に決める。

| 記録 | 保存する(q,b,r) | n=0,1,2,3で照合する出力 | Ψの出力 |
|---|---|---|---|
| 1/3下側 | (1/3,−1/3,1/10) | 0,3/10,33/100,333/1000 | L(−2,1/3) |
| 1/3上側 | (1/3,2/3,1/10) | 1,2/5,17/50,167/500 | L(2,1/3) |
| 定数1/3 | (1/3,0,1/10) | 1/3,1/3,1/3,1/3 | L(0,1/3) |
| 2/3下側 | (2/3,−2/3,1/10) | 0,3/5,33/50,333/500 | L(−2,2/3) |
| メンガースポンジの有限段階体積 | (0,1,20/27) | 1,20/27,400/729,8000/19683 | L(2,0) |

この5記録には、形成の復号、4段の応答列、Ψによる導入をそれぞれ付け、15例を保存する。出力を閉形式 `q+br^n` と一段の再帰式の両方で照合する。体積の例は有限段階の有理値と指定したラベル導入を検査するものであり、無限の図形の交わりやその体積を検査器が構成・測定したことにはしない。

循環小数の `_` は、その後の有限桁列を循環部として指定する表示上の区切りである。記録では非負整数部、0から9の有限非循環桁列、非空の循環桁列の3成分を保存する。`0._3` は `(0,[],[3])`、`0._6` は `(0,[],[6])` となる。非循環部の桁数をm、循環部の桁数をs、その桁列を整数として読んだ値をA、Bとすると、厳密値は `whole+A/10^m+B/(10^m(10^s−1))` である。この例は非負小数を対象とし、負号が必要な場合は既存の有理数の符号反転を別に使う。この有限有理式の評価と、下側・上側の手続きを指定することとは異なる。

1/3の例では、n桁の切捨て下端 `d_n=(1−10^(−n))/3` と上端 `u_n=d_n+10^(−n)` を使う。n=1,2,3について、L(−2,1/3)、L(0,1/3)、L(2,1/3)の全てが同じ開区間 `(d_n,u_n)` に入ることをF算術で検査する。接頭桁はそれぞれ3、33、333である。共通する桁は、kの違いや厳密な等値の規則を消さない。

加法の二例は `L(−2,1/3)+L(−2,2/3)=L(−4,1)` と `L(2,1/3)+L(−2,2/3)=L(0,1)` である。前者を厳密な1へ丸めたり、k=−4を−2へ圧縮したりしない。後者は指定したL演算によって厳密な1となる。

v1.5.7で追加した30例を引き継ぐ。内訳はH記録5、再帰応答列5、Ψ導入5、小数記録2、厳密値の読み2、共通接頭桁の区間3、加算2、拒否6である。拒否例はr=1、桁10、空の循環部、虚偽の再帰出力、逆向きのΨ出力、厳密値への非零kの付与を実際に検査へ渡す。結果の真偽を記録しただけの例ではない。検査核は[構造例生成スクリプト](../scripts/generate-concepts.mjs)内の局所処理であり、公開APIやHTMLの実行規則は追加しない。

## 16. v1.5.8：円周率の指定規則と有限の所属証拠

[本文付録B](../manuscripts/A_New_Foundation_of_Mathematics_ja_v1.5.8.md)では、超現実数との比較と、円周率を厳密に指定する構成例を扱う。以下はその有限入力・応答・所属証拠の表示である。上下の無限集合をデータとして保存するのではなく、有限の規則を固定し、有理数qと自然数mの候補をその規則で調べる。

```text
RulePi             := (N(0),N(1))
RatText(q)         := Text(qstr(q))
再帰の有限記録     := List(RulePi,List(List(N(n),RatText(S_n)),…))
所属証拠           := List(RulePi,N(side),Q(q),N(m))
区間応答           := List(RulePi,N(p),N(m),RatText(B_m),RatText(A_m))
所在性の有限選択   := List(RulePi,Q(q),Q(r),N(m),N(side))
```

RulePiの0はこの指定型の局所規則番号、1は仕様版である。他の型のタグ0との無条件の同一視はしない。この規則は `S_0=1`、`S_(n+1)=S_n+(-1)^(n+1)/(2n+3)`、`B_m=4S_(2m+1)`、`A_m=4S_(2m)` を指定する。所属証拠のside=0では `q<B_m`、side=1では `A_m<q` を確認する。

RatTextは既存のUTF-8文字列符号化を用いる。qstrは分母正・既約の `整数/正整数` という正規文字列を作り、検査はqparseで正確な有理数へ戻して計算する。例えばp=3の区間端点の分母は4512611027925であり、分母そのものを単項の自然数として展開すると膨大になる。そこで有限の証拠欄には正規文字列を採用する。これは第2節の直接的なQ表示を変更したものではない。文字列も有限の自然数と対へ戻るため、完成ファイルの基本記号は同じである。

| 内容 | 構造例ID | 件数・検査 |
|---|---|---|
| 規則と版 | `pi-rule` | 1例。局所番号0・仕様版1を照合 |
| 再帰 | `pi-recurrence-two-steps` | 1例。Sの三状態1、2/3、13/15と二段の更新を独立期待値でも照合 |
| 左右の所属 | `pi-lower-witness`、`pi-upper-witness` | 2例。3<B3、A1<7/2を有限有理算術で検査 |
