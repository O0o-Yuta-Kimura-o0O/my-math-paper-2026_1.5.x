# 符号と大きさを保つλ算術 — 論文 v1.5.4 / インタプリタ v8.0.1

旧稿v1.4.1の付録Cから、整数・有理数の演算を純粋なλ項で与える着想を回収した。本版は[本文](../manuscripts/A_New_Foundation_of_Mathematics_ja_v1.5.4.md)の整数表示を維持し、旧稿の差表示へ戻さない。全定義は[インタプリタ](../interpreter/lambda_interpreter_v8.0.1.html)と[概念記号列](concept-examples-v1.5.4.md)に収録する。新規34定義を既存32定義に加えた。

## 1. 整数表示と旧表示の接続

整数は `Pair s n` とする。sはChurch自然数の0または1、nは大きさを表すChurch自然数である。真偽値を符号の代わりに使わない。nが零ならsを0へ正規化する。以下は、この型に属する入力の上での演算であり、任意のλ項の型判定ではない。

| 定義 | 役割 |
|---|---|
| `ZMake s n` | 零の符号を正側へ正規化した整数 |
| `ZSign`, `ZMagnitude` | 符号と大きさの射影 |
| `ZNeg`, `ZAdd`, `ZSub`, `ZMul` | 符号反転・加減乗算 |
| `ZEq`, `ZLeq` | 型付き入力上の等値と順序 |
| `ZFromDiff p n` | 旧稿の差p−nを現在の符号・大きさへ変換 |
| `ZToDiff z` | 非負なら(m,0)、負なら(0,m)という差表示へ変換 |

**対応命題（手書き）。** 本文のChurch自然数演算の対応と整数の定義の下で、これらの整数演算は本文の整数演算を表す。`ZFromDiff p n`はp−nの符号・大きさを返し、`ZFromDiff (Fst (ZToDiff z)) (Snd (ZToDiff z))`はzへβ等価である。

**証明。** 同符号の加法では大きさを加える。異符号なら自然数の大小を比較し、大きい大きさから小さい大きさを切り捨て差で引き、大きい側の符号を付ける。等しい場合の零は`ZMake`が正にする。乗法は符号一致を非負、符号不一致を負として大きさを掛け、同様に零を正にする。いずれの分岐も本文の整数の定義に一致し、使用する自然数計算のλ対応は本文命題2.1と自然数比較の構造帰納から得られる。変換はp≤nの場合とn<pの場合で調べ、逆変換はzの符号で場合分けすればよい。□

この一般対応は手書きであり、有限例のβ証跡から全称命題を推定してはいない。

## 2. 有理数の正規形と、λ計算内の未約分表示

`QRep`は正の非零分母を持つ整数二つの対であり、未約分の分数も許す補助表示である。本文の型Qは既約な正規表示なので、両者を区別する。写像νは、QRepの分子・分母を整数として読み、有理数の既約化を行ってQへ移す。

| 定義 | 入出力・前提 |
|---|---|
| `QRep n d` | 対を作るだけ。dが正・非零であることを外側で要求 |
| `QRepValid r` | 整数対という前提の下で、分母正・非零を検査 |
| `QMake n d` | 整数入力上で分母の符号を正にし、成功値または零分母の失敗値を返す |
| `QRepAdd`, `QRepSub`, `QRepMul`, `QRepNeg` | 有効なQRepを入力し、有効な未約分表示を返す |
| `QRepEq`, `QRepLeq` | 有効な入力について交差積を比較 |
| `QRepInv`, `QRepDiv` | 有効な入力から、成功値または零による除算の失敗値を返す |

例えば`QRepAdd QHalf QHalf`の出力は4/4の表示である。νを通して本文の1/1に対応する。`QRepEq QHalf (QRep ZTwo (ZMake Zero Four))`は真に簡約する。

**対応命題（手書き）。** νは上の有理表示の加減乗算を本文のQの演算へ移し、非零の除数に対する除算も保存する。`QRepEq`の真偽はνによるQの等値に一致する。

**証明。** 加算の表示は(ad+bc,bd)、乗算は(ac,bd)である。b,dが正・非零ならbdも正・非零である。本文の交差積等値と既約化の一意性から、これらをνで正規化した値はQ上の対応する演算に一致する。符号反転・減算も同じ計算であり、除算では除数の分子が非零のときだけQMakeが成功する。交差積の整数等値をλ整数比較で判定するので、QRepEqも本文のQ等値に一致する。順序では正の分母という条件により不等号の向きが保たれる。□

v8.0.1にはλによるgcd・既約化の処理はまだ含めない。νの具体計算には既存の有理算術実装を利用できるが、それをβ簡約の一手として隠していない。

## 3. 失敗も有限の値として区別する

`ResultOk v = λok.λerr.ok v`、`ResultErr e = λok.λerr.err e` とする。零分母のエラーコードはChurch自然数0である。これは成功した有理数の零とは異なる構文・型である。`ResultBind r k = r k ResultErr`によって、成功時だけ次の処理kへ進み、失敗をそのまま渡せる。

`QMake`等の結果を裸のQRepとして射影してはならない。成功側を選ぶ手続きで中身を受け取る。未定義の自由変数をエラー名として返す旧方式を採用せず、有限の選択構造を使う。HTMLの変換上限や不正なλ構文という実行環境の状態は、この数学上の失敗値とは別である。

## 4. 定義展開と簡約の順序

v8.0.0は全ての名前付き定義を先に展開してからβ簡約したため、使われない枝まで大きくなる場合があった。v8.0.1はδ展開とβ簡約を合わせて、木の左端最外の変換位置を選ぶ。根にβ簡約があれば、その引数内部の定義展開より先に処理する。全ての算術計算は引き続き記録されたδとβで行い、ホスト算術への置換はしない。

新戦略名は`leftmost-outermost-interleaved`。証跡の版と戦略の組を検査する。v8.0.0の保存記録は元のδ優先順序で読み直す。`expandedStart`は、処理中に定義表の名前が初めて残らなくなった項を保持し、その時点に未到達ならnullである。新戦略では、それ以前にもβ簡約が現れうる。

名前付き定義の循環は実行前の検査で拒否する。未使用引数中の定義もこの検査の対象なので、未使用の定義を展開せず捨てられるという説明は、受理された非循環の定義表についてのものである。再帰は明示した固定点λ項として表す。

評価側の再帰探索と検査側のスタック探索は別実装とし、β簡約の置換も別実装で再検査する。構文解析など共有する部分まで独立な形式証明を得たとはしない。資源制限と打切り状態は保持する。大きなChurch算術では手数が増えるので、一般的な停止の数学的説明と、HTMLの制限内で評価が完了する範囲は区別する。

## 5. 検査範囲と再現

`node verification/lambda-arithmetic-tests.mjs`で、符号と零、異符号算術、順序、旧表示との変換、未約分有理数、非零条件、失敗値、変換順序、旧証跡の互換性と改変拒否を検査する。既存のλ核の回帰検査も実行する。

[保存済みのλ証跡](../verification/certificates/lambda-examples-v8.0.1.json)は有限例であり、上の一般対応の形式証明ではない。全66定義の構文はfの入れ子へ直接変換し、復号後のα同値を検査する。HTMLの画面操作の検証状態は[検証資料](../verification/README.md)に記録する。
