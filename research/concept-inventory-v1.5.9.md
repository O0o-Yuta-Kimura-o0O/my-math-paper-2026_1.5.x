# 本稿の概念と基本記号列の対応台帳 v1.5.9

本版は「f生成体系」の用語を採用する。Mは「M多項式」、F上のCεとHεは「生成複素数」「生成四元数」、数列を指定する有限記述は「数列生成ラベル」、精度要求に有理区間を返す手続きを指定する有限記述は「区間生成ラベル」、検査に用いる処理履歴は「計算証跡」と呼ぶ。生成ラベルは生成規則・パラメータとの対応を持ち、実行する生成器とその出力を区別する。Fは本文§1.4の名称に従い、Fまたは有限有理式数と表記する（v1.5.8までの本文は、「〇〇実数」という新名称を検討中としていた）。本台帳のFは本文のFεであり、本文§8.10と同じく紛れのない箇所でFと略す。

本版の[付録：fだけでたどる本論文](../appendices/A_New_Foundation_of_Mathematics_ja_v1.5.9_f_only.md)では、ここで説明に使う対の記号も `f(左右の内容)` に置き換える。この文書は、その付録を読むための中間表記と詳細説明を与える。

この台帳は、統合研究稿 v1.5.9 と応用・λ算術・モデル拡張ノート、λ計算核、等式検査器、有理算術・多項式算術・生成ラベル拡張の公開APIと証拠形式、証明支援系への移植（`verification/proof-assistants/`）、メンガーの次元の区間検査（`verification/menger-dimension-tests.mjs`）を照合したものである。v1.5.1以来の著者の指定に従い、**M を有理係数有限多項式とする**。旧稿の整数段数と有理数の対 `(k,q)` は、区別のため **L** と呼ぶ。本版ではG(q,b)からΦで導入する関係子ラベルの一次表示に用い、bを保持する実行記録とは分ける。F は M 同士の分数である。

対象は「本稿で使う概念の種類と、それぞれの有限表示・処理・証拠」である。任意の長さの全記号列、全自然数、全多項式、全プログラムの個別実例を有限ページに印刷するという意味ではない。各種類の形成規則を尽くすことによって、個別の任意の有限例を展開できるようにする。

v1.5.5から、計算開始前に型を指定して算術の全入力・結果を固定する方針、Nの形成検査NatForm、F二つの対から作る独立した数の型Tを引き継ぐ。生成器・厳密演算・対応証明を必須の一組とする統合ラベル案は採用せず、近似は必要時の別操作とする。

完全な記号列の実例とタグの割当は[基本記号列による全構成](concept-symbols-v1.5.9.md)を参照する。本台帳の `Nat`、`Tag`、`Seq`、数名、演算名、型名、変数、角括弧、等号などはすべて**説明用の略記**であり、展開後に追加の原始記号として残すものではない。

## 1. 読み方と共通の符号化

基本構文は次の三つの場合だけとする。

```text
P ::= f() | f(P) | (P,P)
```

Pは本文§2.6の中間表記のメタ記号であり、後続構成子Sや数の型Tとは別である。fだけの付録では、§2.6の変換Eで共通構文 `U ::= f() | f(U) | f(UU)` へ移す。

自然数 n は、基底 `f()` の外側に n 個の `f( )` を付けた木である。対は `(a,b)`、空列は `f()`、先頭 a と残り r の列は `(a,r)` とする。三成分以上の記録は、各欄の順序を決めた上で二つ組の入れ子にする。本台帳で `Record(a,b,c)` と書いたときは、三つの基本成分を持つ新しい構成子ではなく、例えば `(a,(b,(c,f())))` という有限列の略記である。

異なる構文種別を同じ入力内で混在させるときは、`Tag(種類,a,b,…) := (種類の自然数コード,Seq(a,b,…))` とする。このTag/Node構文では右側は引数の有限列であり、零引数なら空列、一引数なら `(a,f())` である。詳細集の汎用JSON外装Jは、種類に応じたpayloadを直接右側へ置く別規約なので区別する。表中のタグ名は詳細集の登録済みタグの役割を説明する略称で、追加の独立した番号表ではない。型ごとに決まった数の表示では、著者の例に合わせ、余分な外側のタグを付けない。型固定の `f()` は自然数の零にも空列にもなるため、型を外した無条件の読み分けはしない。混在させる必要がある場合は型タグを含める。

有限の種類を使う構文、有限文字列、有限の表、有限の証拠木は、この方法で符号化できる。本稿の文字列規約はUTF-8バイト列であり、各バイトを自然数へ変換する。λの束縛変数は束縛距離の自然数で管理し、自由変数はこの文字列規約を使う。いずれも有限の自然数と対に戻る。

表の「表示」は構成データとして表せること、「処理」はそのデータに作用する規則があること、「検査」は特定の検査器がその証拠を受理することを意味する。**表示できることだけから、正しい数であること、演算が停止すること、命題が真であることは従わない。** 結果の証明の種類を表す語（定義、手書き証明、機械検査、実行検査、外部比較）は本文§1.3と§12に従う。機械検査は、一般の命題について本稿の検査器、またはLean 4・Rocq・Agdaが有限の証明を受理したものであり、実行検査は選んだ入力でプログラムを実行して確かめたものである。

元節の「本文」は統合研究稿 v1.5.9 の節番号、「応用」は[応用ノート](applications-v1.5.9.md)、「モデル」は[計算証跡の拡張ノート](trace-extensions-v1.5.9.md)、「λ算術」は[λ整数・分数算術の接続ノート](lambda-arithmetic-v1.5.9.md)の節番号である。既存拡張とv1.5.9までの追加概念は第12節に整理し、v1.5.9で本文に加わった節・結果と、その実装・検査の範囲は12.8にまとめる。円周率の有限例は局所検査であり、汎用公開APIの追加ではない。実装状態はインタプリタv8.0.1と各検証モジュールに対する記述であり、旧v8.0.0の保存証跡は旧戦略のまま再検査する。符号化するだけで入力仕様や数学的保証が変わるわけではない。

## 4. 演算、再帰、停止の根拠

全演算に共通して、(a)手続きの構文木、(b)入力データ、(c)必要な前提の証拠、(d)出力と有限履歴を区別する。以下の「式」は説明用であり、処理として表す際は演算タグ・引数列・場合分け・再帰参照を持つ有限構文木にする。既存のJS関数名を自然数に置き換えるだけで、演算の中身が純粋λで書かれたことにはならない。

| 概念 | 構成データ | 基本符号化との関係 | 条件・規則・実装状態 | 元節 |
|---|---|---|---|---|
| 再帰定義 | 関数番号、引数、基底場合、後続場合の式 | 各欄の有限構文木 | 再帰の参照は有限コード。全出力の無限列は保存しない。大きさが減る規則で定めた値は一つに決まる（定理10.4） | 本文2.5、3.1、10.6 |
| 自然数加算 | `Add(a,0)=a`、`Add(a,Sb)=S(Add(a,b))` | 二つの定義等式の有限コード | 第二引数が縮む。定義と13個のNat一般命題を区別。Lean 4・Rocq・Agdaでは規則の二行による定義 | 本文3.1–3.2、10.2、10.7 |
| 自然数乗算 | `Mul(a,0)=0`、`Mul(a,Sb)=Add(Mul(a,b),a)` | 同上 | 加算の停止と第二引数の下降を使用 | 本文3.1、3.3 |

## 5. λ計算とインタプリタの概念

λ項の符号化では自由変数、束縛変数、抽象、適用を異なるタグで分ける。指定の記号だけの木へ変換したものは**λ項を表すデータ**である。そのままHTMLの現在の入力欄へ貼れば実行されるという仕様ではない。HTMLは `λx.M` や `M N` などの表層構文を受け取る。

| 概念 | 構成データ | 基本符号化との関係 | 条件・規則・実装状態 | 元節 |

| 自由変数 | `Tag(Free,名前コード)` | 自然数タグと文字列/番号 | 未定義の自由名を数と自動判定しない | 本文2.2、2.6、λ核 |

## 6. 命題、推論、一般証明

この節では、本稿がすでに使う等式・帰納規則と、一般の論理式を表示するための追加構文案を区別する。量化記号や論理結合子は有限タグとして符号化できるが、既存の `equational-checker.mjs` は完全な一階述語論理の検査器ではない。本文§2.6のとおり、命題と証明木の符号は保存のための表示であり、この形の証明木を読む検査器は収録していない。§10.2の等式証明検査器は別の形式（JSON）の証明データを読む。

## 11. 記号列に戻せても、そこから自動的には得られないもの

| 問題・概念 | 有限記号列として保持できるもの | この時点で保証されないもの |
|---|---|---|
| すべての自然数・全多項式 | 形成規則、任意の一例 | 全例を完成した一列として印刷・保存すること |
| 無限に続く生成過程 | 有限のプログラム、パラメータ、既実行の有限履歴 | 実行し終わった無限履歴や最後の有理値 |
| 任意の関数 | 有限で指定されたプログラム/式 | 有限に指定していない任意の関数の全表現 |
| 停止 | 特定の有限終了履歴、または一般停止証明 | 任意プログラムの停止を自動判定する機能 |
| 生成器の等値 | 同値関係の仕様、具体的同値証明 | 任意の二生成器の全入力上の同値を決める機能 |
| 任意命題の真偽 | 命題の有限構文と、得られた証明 | 任意命題をコード化すれば真偽も決まるという主張 |
| 無矛盾性・独立性 | その主張自体の論理式 | ZF/ZFCを内部で採用しないことから直ちに無矛盾性や独立性が出るという主張。本稿は体系の無矛盾性も既存の理論からの独立性も主張しない |
| 完備性・全古典実数の回収 | 性質の命題コード、命題11.1の反例の記述 | 本稿がそれを満たすという証明。Fεでは完備性が成り立たない（命題11.1）。全古典実数の回収も目標にしない |
| F内の√2 | 方程式のコード、Fに解がないという証明 | Fの元としての解。精度応答生成器は別の型。平方が二の正の元はTのσ（定理8.9） |
| 通常の円周率 | Π生成器と有限の幅・入れ子証拠、有理切断記述π_cut | 通常の円周率との同定は命題B.5の外部比較（積分表示とアルキメデス性）であり、機械検査していない。円の長さや面積を内部で構成したのではない |
| 指数関数、一般の連分数、他の級数 | 具体的に定義した有限生成規則のコード | 全てについての停止・誤差・同値仕様。原資料の未確定式を有効な定義とはしない（本文13の課題） |
| 全域標準部 | 「全域化したい」という命題のコード | εを零へ送りながら全F上で乗法を保存する写像。本文の反例と両立しない |
| GからのΦ導入と#/♭ | 指定規則Φ(G(q,b))=(2sgn(b),q)、共通部分列の証明、非加法性の反例 | 任意生成器の同値判定、点ごとの加法を保存する商写像。Lのkを演算後に符号だけへ圧縮すること。係数を捨て、加算を保存し、加法消去と非零性も保つ導入（本文7.3で否定） |
| M内の一段の隣接 | pとp+εの有限表示 | 中間がないという主張。有理係数Mにはp+ε/2がある |
| 四元数 | F成分の有限記号列と共役を含む演算式 | 積の可換性、既存HTML/APIでの実装済みという主張 |
| 汎用論理 | ∧、∨、→、∀、∃等の有限構文 | 既存Nat/Seq等式checkerがそれら全部を検証するという主張。自然演繹の全体を検査する検査器は本文13の課題 |
| 全処理の純粋λ化 | 対象構文を基本木へ符号化したもの | BigInt算術や多項式APIが既に純粋β簡約で動いているという主張。λの中でgcdと既約化を書くことは本文13の課題 |
| BigIntによる厳密算術 | 桁の並びによる計算の記録、二進の加法の規則と命題10.6 | BigIntの実装そのものの正しさ。処理系を信頼する範囲に含まれる（本文10.3、10.6） |
| 計算モデルからの独立 | 定理10.4の形の規則、各モデルが規則どおりに計算することの証明 | 条件を確かめていないモデルでの値・証拠の一致。計算できる関数の範囲についての主張（Church–Turingのテーゼは前提にしない） |
| 検査器自身の正しさ | コード、テスト、独立な再検査の結果、証明支援系による別の言語・別の実装での検査 | 同じ検査器の自己報告だけによる無前提の正当化。証明支援系の検査器と処理系も別の信頼の対象（本文10.3） |
| 0.999…の値 | 記録`0._9`、生成処理H(1,−1,1/10)、Ψの出力(−2,1) | 構成を指定しない記録だけから決まる値。定理A.3は規約の下の主張であり、通常の実数での0.999…=1の反証ではない |
| メンガーのスポンジの次元 | 有理切断記述d_cut、累乗の比較による有限の証拠 | 一般の次元論、対数関数・Hausdorff測度の内部構成。通常の次元との一致は外部比較 |
| すべての数を含む型 | 型ごとの表示と、個別に定めた埋込み | すべての数を一度に与える型。σとπ_cutを含む式は、そのための型を定めるまで計算しない（本文11.4、13） |
| 選択公理に依存する一般の存在定理 | 個別の場面での構成と証人 | すべてのベクトル空間の基底、一般のハーン＝バナッハの定理、チコノフの定理などを定理として与えること（本文11.5）。選択公理の否定も主張しない |
| 外部操作、日時、ファイルの作者 | 有限の記録文字列・ハッシュ等 | 記録を作った時刻・人物・手動停止の発生自体の認証 |

この台帳でいう「基本的にすべて表せる」は、**明示的に定義した有限データ、有限プログラム、有限命題、有限証明を、共通の有限木へ戻せる**という意味である。それぞれのデータに何を意味させ、どの処理を許し、どの証拠を受理するかは、表に挙げた型形成条件・計算規則・推論規則によって与える。
