# f生成体系 — 数学の新しい基礎づけ

木村祐太の原構想を基に、再帰的な記号構成と、有限の処理履歴・証明データによる検証を整備する研究です。ZF/ZFC を内部の公理として採用せず、使用する構文・計算・推論規則を明示します。

現在の版は **論文 v1.5.4 / λ計算インタプリタ v8.0.1** です。Mを有理係数有限多項式、FをM同士の分数として定めています。

本版は「f生成体系」の用語を採用する。Mは「M多項式」、F上のCεとHεは「生成複素数」「生成四元数」、数列を指定する有限記述は「数列生成ラベル」、精度要求に有理区間を返す手続きを指定する有限記述は「区間生成ラベル」、検査に用いる処理履歴は「計算証跡」と呼ぶ。生成ラベルは生成規則・パラメータとの対応を持ち、実行する生成器とその出力を区別する。Fの「〇〇実数」という新名称は検討中であり、この版ではFまたは有限有理式数と表記する。

v1.5.4では、別稿 `Generative_Reals_ja_v1.4.1.md` から有限構成と証拠に関する着想を回収しました。Fを有理数係数の多項式比として保ち、平方根等の区間生成ラベルを別の型として扱います。別稿の係数体への商構成や、ZF・PA等を固定した内部基礎は採用していません。

## この版で確認できること

自然数の13個、列連結の3個の一般等式を、型付き等式・構造帰納の有限証明として検査します。Fεの四則・gcd正規化・順序・定義域を限定した標準部、qlim、既存の平方根・Leibniz列・多項式の有限計算も引き続き扱います。今回の追加は次の通りです。

- Lの加法・順序とQの演算を順序体へ保存する条件の下で、有限の四則で生成される部分がFεに対応することを証明。
- 生成ラベルを「規則・パラメータ・仕様・証拠」で記述し、区間の加減乗除、分母の非零分離、精度配分を明示。
- 一般交代和、Newton法と二分法の応答整合、誤差率付き数列からの有限区間生成を定義・証明。収録した生成規則の具体的応答を厳密算術で再検査。
- 有理精度とFεの全精度を区別し、逆数の差商、有限長方形和と形式定積分の誤差を証明。
- 加法群の3手、逆射の5手の等式証跡と、レジスタ機械による加算の全遷移を検査。生成ラベルの整数平行移動から逆射を持つ圏も構成。
- λインタプリタに符号付き整数と未約分分数の補助型QRepを追加。内蔵λ定義は66個です。QRepと既約なQを区別し、λによるgcd・既約化は含めません。
- δ展開とβ簡約を合わせた左端最外の処理に改訂し、使われない枝の先行展開を抑制。旧v8.0.0の証跡は元の戦略で再検査できます。

整数・QRepの追加演算はλ定義とδ・β証跡によります。Fεや区間生成ラベルの具体計算はJavaScriptの厳密算術による別形式の証拠であり、全演算をHTMLの純粋λライブラリに移したものではありません。

各成果の証明状態は論文内で明示しています。手書きの一般証明、機械検証した一般証明、具体的な有限計算、未確定の解釈を区別します。`qlim` と隣接記号の最終的な同一視、およびそれらと形式的な無限小のモデルとの関係は引き続き検討します。体系名と周辺用語は確定し、Fの「〇〇実数」という名称を検討しています。

v1.5.1では `f()`・`f(t)`・`(t,u)` による有限記号列の仕様、数から四元数の表示、型・λ構文・命題・証明・生成器・履歴の表示を追加しました。全内蔵λ定義と、既存の四種類の証拠ファイルを省略なく基本記号へ変換し、復号して再検査しています。符号化できることと、その内容が実行可能・証明済みであることは資料内で区別します。

v1.5.2では対も `f(左右の内容)` に統一しました。その版の付録には構造を直接示す167例と4種類の完全な証拠束を収録し、後部に本文全文と実行定義の可逆な文字列保存を加えました。後部の保存を、全手書き証明の形式化とは区別します。

現在の付録では221件の構造例を収録し、新しいλ定義と追加証拠束まで同じfの構文へ戻します。本文は導入部と13章の14片、数学実装は6ソースを可逆に保存し、6種類の証拠束は復号後にそれぞれの検査器へ渡します。構造の直接表示と、文章・コードの文字列保存を区別しています。

## 検証を実行する

Node.js 20 以降を使います。外部パッケージは不要です。

```sh
node scripts/verify.mjs
node scripts/generate-evidence.mjs
node scripts/generate-concepts.mjs --check
node scripts/generate-f-only.mjs --check
```

今回の9群・157テストはすべて成功しました。[実装の検査報告](verification/verification-report.json) と [証拠の再検査報告](verification/evidence-report.json) に結果を保存しています。この件数は、実装の回帰・拒否検査の数であり、一般数学定理の数ではありません。実ブラウザの操作確認は、ローカルファイルの表示がブラウザの安全ポリシーで拒否されたため未実施です。制約を迂回せず、計算核・証跡・UIスクリプトの構文をコードとして検査しています。

基本記号の資料を作り直す場合は、`node scripts/generate-concepts.mjs`、`node scripts/generate-f-only.mjs` の順に実行します。保存済みの公開用コピーを確認する場合は `--check` を付け、配布ファイルを変更せず検査できます。

## ファイルとバージョンの運用

論文は `A_New_Foundation_of_Mathematics_ja_v1.5.0.md` から開始し、改訂ごとに `v1.5.1`、`v1.5.2`、`v1.5.3`、`v1.5.4` のように増やします。インタプリタは `lambda_interpreter_v8.0.0.html` から開始し、独立に版を管理します。確定した過去版は保存し、現在の対象を `release.json` に記録します。v1.5.0 の作成中の修正は初版の校正に含めます。

作業フォルダでは原資料を `origin/` に保持しています。GitHub にアップロードするための複製は `output/` にあり、最新の論文・インタプリタ・監査・応用・検証資料を、相対リンクが保たれるフォルダ構成でまとめます。原資料の過去版は配布用の複製に混在させません。

作業フォルダから配布用の複製を更新するコマンドは `node scripts/package-release.mjs` です。配布済みの `output/` 内でこのコマンドを実行する必要はありません。出力の `MANIFEST.json` にファイル一覧・版・SHA-256 を記録し、複製と作業用ファイルのバイト一致を確認します。出力先で手動編集されたファイルは自動的に上書きしません。

GitHub には `output/` の**中身**をアップロードすると、この README と相対リンクがそのまま使えます。

この作業で行うのは最新ファイルの複製と検査です。GitHubへのアップロードや公開は行っていません。
