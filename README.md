# f生成体系 — 数学の新しい基礎づけ

木村祐太の原構想を基に、再帰的な記号構成と、有限の処理履歴・証明データによる検証を整備する研究です。ZF/ZFC を内部の公理として採用せず、使用する構文・計算・推論規則を明示します。

[English](README.en.md)

現在の版は **論文日本語版・英語版 v1.5.8 / λ計算インタプリタ v8.0.1** です。Mを有理係数有限多項式、FεをM同士の分数として定め、必要な数と演算を、共通の有限構文・型別規則・証拠によって追加していきます。

v1.5.8では、付録Bに超現実数との比較と円周率の厳密な構成例を追加しました。有限記述・計算・証拠検査の利点を具体化し、表現範囲や一般の等号判定の限界も明示します。円周率は有理切断記述という別の型で構成し、既存の無限小を含む数の等号や演算を変更しません。通常の円周率との対応は、外部の解析学を用いる比較定理として分けて証明します。

v1.5.7では、本文末の付録Aに小数とメンガーのスポンジの比較例を追加しました。`0._3` は循環桁の指定であり、それだけでラベルを決めません。有理数1/3を厳密に保ち、有理評価・下側生成・上側生成を区別します。等比生成族Hの有限契約と導入を定め、スポンジの体積生成処理からの関係子ラベルを `0##` とします。直観主義の推論方針、Church表示との対応、関連研究を補強しました。バナッハ＝タルスキーは著者の希望により保留し、研究の動機と決定事項を[記録](research/author-design-decisions-v1.5.8.md)しています。

v1.5.6では、正の有理数bを使う `q+b/(n+1)` の生成記録から、bの大きさを捨てて共通の `q##` を導入します。生成記録は実行のためにbを保持し、導入先のLは有理成分と#の個数を保持します。再帰回数n、#の個数k、要求精度pを区別します。導入は逐点加算を保存せず、ラベルの演算では `0## + 0## = 0####` となるため、非零性と加法消去を両立できます。

近似処理と挟み込みは、その対象と保証を明示して維持します。qへの生成誤差をq##の誤差へ自動的に読み替えず、`q## = q+2ε` と表示先の順序を使って有理精度の保証を示します。区間端点への関係子の付与だけで、全精度の応答に共通する厳密な元を作ったとはしません。

本版は「f生成体系」の用語を採用する。Mは「M多項式」、F上のCεとHεは「生成複素数」「生成四元数」、数列を指定する有限記述は「数列生成ラベル」、精度要求に有理区間を返す手続きを指定する有限記述は「区間生成ラベル」、検査に用いる処理履歴は「計算証跡」と呼ぶ。生成ラベルは生成規則・パラメータとの対応を持ち、実行する生成器とその出力を区別する。Fの「〇〇実数」という新名称は検討中であり、この版ではFまたは有限有理式数と表記する。

v1.5.5では、使用する型を計算前に固定する進め方を明示しました。小さい例として、共通構文Uの有限木が自然数表示の形かを調べ、真偽値を返す再帰判定 `NatForm` を示します。さらに、Fεの対 `(a,b)` を使う正根拡張Tを例に、`σ²=2` を満たす数と演算を有限規則で追加します。Newton法や二分法は近似応答が必要なときに選ぶ処理であり、すべての数に生成器を付けるための必須構成にはしません。

v1.5.4では、別稿 `Generative_Reals_ja_v1.4.1.md` から有限構成と証拠に関する着想を回収しました。Fを有理数係数の多項式比として保ち、平方根等の区間生成ラベルを別の型として扱います。別稿の係数体への商構成や、ZF・PA等を固定した内部基礎は採用していません。

## この版で確認できること

自然数の13個、列連結の3個の一般等式を、型付き等式・構造帰納の有限証明として検査します。Fεの四則・gcd正規化・順序・定義域を限定した標準部、qlim、既存の平方根・Leibniz列・多項式の有限計算も引き続き扱います。v1.5.4までの基盤として、次の構成・証拠を引き継いでいます。

- Lの加法・順序とQの演算を順序体へ保存する条件の下で、有限の四則で生成される部分がFεに対応することを証明。
- 生成ラベルを「規則・パラメータ・仕様・証拠」で記述し、区間の加減乗除、分母の非零分離、精度配分を明示。
- 一般交代和、Newton法と二分法の応答整合、誤差率付き数列からの有限区間生成を定義・証明。収録した生成規則の具体的応答を厳密算術で再検査。
- 有理精度とFεの全精度を区別し、逆数の差商、有限長方形和と形式定積分の誤差を証明。
- 加法群の3手、逆射の5手の等式証跡と、レジスタ機械による加算の全遷移を検査。生成ラベルの整数平行移動から逆射を持つ圏も構成。
- λインタプリタに符号付き整数と未約分分数の補助型QRepを追加。内蔵λ定義は66個です。QRepと既約なQを区別し、λによるgcd・既約化は含めません。
- δ展開とβ簡約を合わせた左端最外の処理に改訂し、使われない枝の先行展開を抑制。旧v8.0.0の証跡は元の戦略で再検査できます。

整数・QRepの追加演算はλ定義とδ・β証跡によります。Fεや区間生成ラベルの具体計算はJavaScriptの厳密算術による別形式の証拠であり、全演算をHTMLの純粋λライブラリに移したものではありません。

v1.5.5で追加したNatFormとTの一般保証は手書き証明です。構造例の符号化・復号や具体計算の検査を、その一般定理の機械証明とは扱いません。

各成果の証明状態は論文内で明示しています。手書きの一般証明、機械検証した一般証明、具体的な有限計算、未確定の解釈を区別します。標準族の `qlim` から関係子ラベルへの導入はv1.5.6で定めました。標準族以外への導入や任意の生成器の等値判定は、引き続き個別の条件を要します。体系名と周辺用語は確定し、Fの「〇〇実数」という名称を検討しています。

v1.5.1では `f()`・`f(t)`・`(t,u)` による有限記号列の仕様、数から四元数の表示、型・λ構文・命題・証明・生成器・履歴の表示を追加しました。全内蔵λ定義と、既存の四種類の証拠ファイルを省略なく基本記号へ変換し、復号して再検査しています。符号化できることと、その内容が実行可能・証明済みであることは資料内で区別します。

## 検証を実行する

Node.js 20 以降を使います。外部パッケージは不要です。

```sh
node scripts/verify.mjs
node scripts/generate-evidence.mjs
node scripts/generate-concepts.mjs --check
node scripts/generate-f-only.mjs --check
node scripts/check-english-translation.mjs --check
node scripts/generate-english-appendix.mjs --check
```

実行した検査群と成否は、[実装の検査報告](verification/verification-report.json) と [証拠の再検査報告](verification/evidence-report.json) を参照してください。報告内のテスト件数は、実装の回帰・拒否検査の数であり、一般数学定理の数ではありません。実ブラウザの操作確認は、ローカルファイルの表示がブラウザの安全ポリシーで拒否されたため未実施です。制約を迂回せず、計算核・証跡・UIスクリプトの構文をコードとして検査しています。

基本記号の資料を作り直す場合は、`node scripts/generate-concepts.mjs`、`node scripts/generate-f-only.mjs` の順に実行します。保存済みの公開用コピーを確認する場合は `--check` を付け、配布ファイルを変更せず検査できます。

## ファイルとバージョンの運用

論文は `A_New_Foundation_of_Mathematics_ja_v1.5.0.md` から開始し、改訂ごとに `v1.5.1`、`v1.5.2`、`v1.5.3`、`v1.5.4`、`v1.5.5`、`v1.5.6`、`v1.5.7`、`v1.5.8` のように増やします。インタプリタは `lambda_interpreter_v8.0.0.html` から開始し、独立に版を管理します。確定した過去版は保存し、現在の対象を `release.json` に記録します。v1.5.0 の作成中の修正は初版の校正に含めます。

作業フォルダでは原資料を `origin/` に保持しています。GitHub にアップロードするための複製は `output/` にあり、最新の論文・インタプリタ・監査・応用・検証資料を、相対リンクが保たれるフォルダ構成でまとめます。原資料の過去版は配布用の複製に混在させません。

作業フォルダから配布用の複製を更新するコマンドは `node scripts/package-release.mjs` です。配布済みの `output/` 内でこのコマンドを実行する必要はありません。出力の `MANIFEST.json` にファイル一覧・版・SHA-256 を記録し、複製と作業用ファイルのバイト一致を確認します。出力先で手動編集されたファイルは自動的に上書きしません。更新対象はこのmanifestが管理する最新論文の配布物です。公開用フォルダへコピーする対象は、このmanifestに列挙されたファイルと `MANIFEST.json` 自身です。

GitHubへの更新では、`output/MANIFEST.json` に列挙されたファイルと `MANIFEST.json` 自身を、既存の公開配置に合わせて追加・上書きします。公開用フォルダは `output/` と分け、SNS等から参照される旧版とそのリンク先を元の場所に残します。コピー元にないファイルを削除する同期は行いません。非公開の原稿やメモはコピー対象に含めません。

この作業で行うのは最新ファイルの複製と検査です。GitHubへのアップロードや公開は行っていません。
